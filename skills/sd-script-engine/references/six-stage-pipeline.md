# 六阶段编剧链总流程

> 精编自《灵境AI剧本改编 skill》（6阶段编剧链）

本文件是 sd-script-engine 的主流程权威：六阶段的进入条件、产出物、门禁，两种制作模式，第⑤阶段正式剧本的完整写作规范，以及授权后的精修/重写。各阶段的专项细则路由到其余四份规则库。

## 一、六阶段总览

```text
①来源登记 → ② IP 与角色开发 → ③全剧开发圣经 → ④分集规划 → ⑤正式剧本 → ⑥五席圆桌审核
→ 用户决定〔接受，或 精修/重写（04F）→ ⑥〕
```

到用户接受全部剧本批次为止。禁止在本链内创建资产库、角色资产 ID、导演分镜、灯光剪辑方案、视频提示词、图片、音频或视频。

### 事实权威链（全链适用）

`用户提供的小说事实 > 锁定IP > 锁定故事圣经 > 锁定分集规划 > 当前剧本 > 圆桌意见`

区分 `FACT`、`INFERENCE`、`ASSUMPTION`、`USER_OVERRIDE` 和 `OPEN_ITEM`。市场套路、评审偏好或模型推断不得改写成小说事实。

### 阶段门禁与校验方式

- 每阶段只消费已锁定（`LOCKED`）并通过校验清单的上游成果；上游 `STALE`、版本不一致或来源覆盖不完整时停止并报告。
- 阶段校验一律按「阶段校验清单」逐项人工核对（见 SKILL.md 第七节）：全部 `PASS` 且 `failure_flags` 为空才能锁定；失败标记只能通过修改正文或账本消除，不得手工清空数组。
- 任何新批次都以文件账本为权威，不依赖聊天窗口保留完整上下文。

## 二、两种制作模式

### A. 逐步确认（STEPWISE）

每次只完成一个未锁定阶段：

1. 检查来源和上游版本。
2. 完整读取当前阶段规则库和必读章节。
3. 生成该阶段全部文件。
4. 执行语义自检和阶段校验清单核对。
5. 置为 `AWAITING_CONFIRMATION` 并停止。

用户确认后才锁定并继续。阶段④开始前另行执行分集选择门；阶段⑤按连续批次生产，每批完成后必须进入⑥。

### B. 完整执行（FULL_SCRIPT_PIPELINE）

自动执行阶段②—⑤，但仍遵守所有锁定门：

- 阶段②—③校验清单失败立即停止。
- 用户未指定集数时，阶段④使用智能推荐。
- 用户指定集数超出容量区间时，必须暂停说明代价并取得二次确认。
- 长剧仍按连续批次写作，不能依赖聊天窗口维持状态。
- 每批⑥结束后无条件暂停；完整执行不代表可以替用户决定是否修改。

## 三、阶段①来源登记（摘要）

进入条件：用户已提供全部材料，模式已选定。

核心动作：建立 `SOURCE_MANIFEST.json`（每块记录 `source_id`、标识、章节起止、范围、内容哈希、读取/提取/合并状态）；自动识别材料类型（完整小说/节选/大纲/已有剧本/续接项目）；长篇按自然章节边界分块做 P1/P2 事实提取；同时启动全篇角色证据扫描。

产出：`00_source/SOURCE_MANIFEST.json`、`PROJECT_MANIFEST.md`、`SCRIPT_PIPELINE_STATE.json` 初始化。

门禁：全部已提供来源完成登记与哈希、别名和时间状态冲突已处理、`unresolved_ranges` 为空。细则见 [source-registration.md](source-registration.md)。

## 四、阶段② IP 与角色开发 与 阶段③全剧开发圣经（摘要）

- ② IP 与角色开发：从来源提炼角色 IP（S/A/B/C 层级、灵魂引擎、观众喜爱路径、五类记忆点、关系专属性、表演声音、视觉身份、成长地图、类型适配），交付 `01_ip/` 六件套（`01_IP_BIBLE.md`、`IP_CANON_MANIFEST.json`、`VISUAL_IDENTITY_BIBLE.md`、`STYLE_PROFILE.md`、`IP_PRESENTATION_PACKAGE.md`、`HANDOFF_CARD.md`）。门禁：IP 十二项质量门全 PASS。
- ③全剧开发圣经：三遍通读（观众/事实/改编）+ P1/P2/P3 流程，建立创意 DNA、类型受众合同、四层梗概、世界观价值合同、人物故事小传、大弧架构、七类改编蓝图、钩子候选池与容量诊断，交付 `02_story/` 十件套。门禁：故事十五项质量门全 PASS；`exact_count_locked` 必须为 `false`。**★ 另必须附《世界锚卡》与《人物锚卡》**（`story-bible-and-ip.md` §1.11）——**世界锚卡＝年份/地域/技术时代 + 禁用元素清单 + 必现元素清单；人物锚卡＝年龄段 + 身高体型 + 身份外观三件套（职业标识物/服装形制/气质体态）+ 反漂移清单**。二者抄进 `HANDOFF_CARD.md` 禁改项随稿传下游；**缺任一张 = 阶段③ 未完成**（由来：粉丝实测「2035 年南京出片成 80 年代破街烂车、外卖员出成协警、年龄与身材比例卡不到」）。

完整规范见 [story-bible-and-ip.md](story-bible-and-ip.md)。

## 五、阶段④分集规划（摘要）

进入条件：①—③已锁定，分集选择门已过（`SMART_RECOMMENDED` / `USER_DEFINED`）。

核心动作：九遍策划流程——锁定精确集数、标注事件归属与可压缩性、建立开篇爬坡与大弧、建立完整单集故事单元、观众理解契约、局部兑现与追看契约、情绪与 IP 编排、边界连续性防重复、三种观众终审。

产出：`03_episodes/` 六件套（`03_EPISODE_PLAN.md`、`EPISODE_PLAN_MANIFEST.json`、`VIEWER_RETENTION_MAP.md`、`EVENT_COVERAGE.md`、`HOOK_PAYOFF_LEDGER.md`、`HANDOFF_CARD.md`）。

门禁：每个事件唯一主归属；每集理解/行动/兑现/追看/情绪/连续性/IP 字段完整；钩子种下集与兑现集一致；不存在连续三集同一冲突公式；全部质量门 PASS。细则见 [episode-planning.md](episode-planning.md)。

## 六、阶段⑤正式剧本：原作忠实剧本主编

> 本节为第⑤阶段的完整写作规范。台词规则与总控「台词七维诊断」**配合使用**：总控七维为准绳，本节规则补充剧本层执行口径，二者冲突时以总控裁定为准。

### 6.1 核心结果

把小说内容「剧本化升级」，不是脱离小说重新编故事。正式剧本必须同时满足：

1. 原作主线、人物动机、关键关系、世界规则、关键因果、趣味看点和关键台词功能不丢。
2. 每集是能连续复述的完整故事单元，不是梗概、节拍清单、名场面拼贴或一场戏的上下半段。
3. IP 灵魂选择、缺点后果、专属行为、人物声音和关系信号进入正文行动，不靠设定说明代替。
4. 冲突由目标、策略、反制、换策和代价推进；先兑现本集所得，再落下有兑现位置的主钩子。
5. 长剧可分批、分集交付，但批次边界不能改变全剧方向、人物状态、时间线、伏笔或钩子债务。
6. 每集同时满足连续观看与单集观看：首场前 10 秒有来源支持的爆点、最小处境、行动问题和 `WHY_NOW`，上一集最后变化直接触发下一集第一动作。

### 6.2 门禁与输入

只消费已锁定并通过校验的阶段①—④：`PROJECT_PROFILE`、`01_IP_BIBLE`、`IP_CANON_MANIFEST.json`、`IP_ARC_BINDINGS`、`02_STORY_BIBLE`、`STORY_CANON_MANIFEST.json`、`03_EPISODE_PLAN`、`EPISODE_PLAN_MANIFEST.json`。

若上游版本、人物 ID、事件 ID、集数或钩子账本不一致，立即停止并输出 `BLOCKED_REPORT`。不得凭记忆补齐冲突版本。

每集必须完整消费 `episode_thesis`、`one_sentence_recall`、`story_unit`、`comprehension_contract`、`retention_contract`、`emotion_curve`、`timeline`、`ip_dramatization`、`primary_events`、`callbacks` 和 `source_trace`，不能只读取集标题或一句摘要。

`STEPWISE` 只写用户确认的集数或批次。`FULL_SCRIPT_PIPELINE` 同样一次只完成一个连续批次；本批校验通过后输出交接包并停止，由总控单独发起圆桌评审。任何模式都不得绕过审核后的用户质量选择继续写下一批。

### 6.3 来源权威链与退回规则

事实权威从高到低：`小说原文 → 故事圣经 → 分集卡 → 正式剧本`。

阶段⑤每写一集都必须重新读取该集 `source_trace` 对应的小说原文、关键台词原文和必要前后文，不能只看摘要继续扩写。

若要改变以下任一内容，退回阶段④修订并重新锁定，不得在剧本里静默修改：

- `primary_events`
- `episode_thesis` 或 `one_sentence_recall`
- `local_payoff`
- `primary_hook_id`、`payoff_episode` 或 `next_episode_first_action`
- 核心角色及 IP 版本
- 事件事实生效顺序、人物知识边界或来源压力条件

允许的改编动作（每项来源内容只能标记一种）：

- `KEEP`：保留事实、功能和发生条件。
- `COMPRESS`：压缩重复叙述或过程，但保留因果、动机、代价和结果。
- `MERGE`：合并同功能过程、场次或次要人物功能，不改变责任与关系位置。
- `VISUALIZE`：把心理和叙述转成可见行动、反应、空间、道具或策略对白。
- `REORDER_AUTHORIZED`：只执行上游已授权的重排，并保护知识边界和事实生效顺序。
- `DELETE_REDUNDANT`：删除无独立功能的重复内容，并完成删减影响审计。
- `CONNECTIVE_INFERENCE`：补充不改变主线事实的入场、移动、反应、职业流程和连接对白。

禁止新增或替换原作的关键身份、能力、秘密、证据、规则、关系、责任、胜负、谜底和结局；禁止用流行套路覆盖原作人物；禁止把「可能、以后、条件成立」擅自写成「已经、现在、必然」。`MUST_KEEP` 与本集 `primary_events` 不得标记 `DELETE_REDUNDANT`。任何删减都要证明因果链、人物动机、伏笔回收、关系变化和后续理解没有断裂。四级比对、删减影响审计与关键台词保护的完整规范见 [source-registration.md](source-registration.md) 第三、四节。

### 6.4 主笔标准（head-writer-standard）

短剧主编对「项目能否持续兑现受众承诺并被生产执行」负责，不只是修改几句台词。

**立项与受众承诺**：把题材标签改写成可检验的受众承诺；判断一句话卖点是否包含人物、异常处境、行动目标和失败代价；明确创新点改变的是冲突机制还是人物选择；设定开篇证明、阶段兑现和最终情感回收，保证前期卖点与结局不是两部作品。

**编剧室与长剧分批管理**：主编向编剧室提供已锁定的 IP、故事圣经、事件覆盖、分集卡、人物声音和版本号；每位编剧只在获分配集数内创作。交稿时必须附：本集承诺、来源事件、状态变化、钩子兑现、疑问项和改动影响。主编统一：人物称呼、语气、秘密和知识边界；道具归属、伤势、服装、地点和时间连续性；同一伏笔的种下、提醒和回收措辞；大弧节奏、商业节点与情感主线；场次格式、时长估算和版本命名。发生上游改动时先标记受影响剧本为 `STALE`，列出受影响集数，不允许口头改完后继续沿用旧清单。

**七轮审稿**（逐集锁定前依次执行，任一轮 `REVISE`/`REWRITE` 先改正文再复审）：

1. **来源、故事与因果**：核对四级来源、改编动作和删减审计，再检查目标、阻力、策略、反制、转折、局部兑现和钩子。主角必须主动做事；反转必须有来源或已建立证据；爽点必须有准备、见证和结果。
2. **人物与关系**：行动是否来自角色欲望、恐惧和当前信息；对手是否有有效目标；关系场是否改变下一步选择。人物突然变蠢、突然全知或突然变心时退回重写。
3. **台词与表演**：逐句标注功能，检查角色声音、潜台词、抢话、停顿和可见反应；抽取主语、对象、条件与后果确认可复述；删除重复解释和可被动作替代的说明；关键情感台词前后要有行为支撑。
4. **连续性与格式**：核对集号、场号、内外景、日夜、出场人物、入场/退出状态、人物知识、伤势、道具、界面/文件首次出现和承接动作。执行 `STANDALONE_EPISODE_TEST`、`LAST_FRAME_FIRST_ACTION_TEST` 和 `FLASHBACK_ANCHOR_TEST`。
5. **桌读、时长与制作成本**：对白按角色语速朗读，动作加入准备、反应和停顿。超时先去重复，再合并同功能场次。预算问题用场面调度和信息载体解决，不擅自删主线。
6. **合规与风险**：审查自伤、极端暴力、未成年人、歧视羞辱、性暗示、违法模仿、真实人物肖像和声音等风险；记录问题、功能、替代呈现和上下游影响，再按项目尺度修订。
7. **去元数据通读与观众复审**：隐藏所有工作字段，只朗读正文；以编剧、导演和第一次观看的观众回答故事能否连续复述、冲突是否由行动推进、关系转变是否有行为依据、代价是否真的发生。技术字段全部通过但正文像会议纪要时，仍应 `REWRITE`。

**判定标准**：`PASS`（七轮全过，可锁定）/ `REVISE`（列出精确修改项后复审）/ `REWRITE`（核心目标不清、因果断裂、人物失真、主事件被删、钩子无兑现或新增无来源重大设定；不能靠润色通过）。

**主编不可做的事**：不能用流行套路覆盖原作人物，不能把更高权力或更多财富当作唯一升级，不能把重复羞辱当冲突，不能为制造卡点拖延已经承诺的答案，也不能在剧本锁定后不登记版本就要求下游继续生产。

### 6.5 全剧先行：SERIES_SCRIPT_STRATEGY

第一集开写前先创建 `04_scripts/SERIES_SCRIPT_STRATEGY.md`（写作宪法），锁定：

- 原始创意、题材机制、受众承诺和全剧一句话行动线。
- 主线、情感线、成长线、关系线、谜团或任务线的优先级。
- 各大弧进入压力、阶段兑现、情绪回报和不可擅改事实。
- 核心人物欲望、恐惧、错误策略、灵魂选择、缺点后果、声音与关系动力。
- 题材专属节奏：爽点/笑点/悬念/情感/动作如何建立、升级、见证和兑现。
- 关键台词保护策略、来源压力、伏笔回收、禁用套路和合规边界。
- 默认单集时长、批次大小、相邻集连读方式和全剧终审条件。

策略文件只统一本剧写法，不能创造小说中不存在的故事答案。

**八层全剧分析**：

1. **原始创意**：一句话说清最不可替代的想象，不写题材标签。
2. **受众承诺**：分别定义情节回报（胜负、破解、成长、逆转、关系变化）、情绪回报（爽、笑、甜、痛、燃、怕、好奇、治愈）、人物回报（为何想继续看这个 IP 选择、犯错、付出和改变）。
3. **全剧行动线**：`谁为了什么长期目标 → 持续面对什么机制性阻力 → 采用什么独特办法 → 失去或改变什么 → 最终必须做什么选择`。
4. **多线优先级**：锁定各线优先级和交汇点；只提供热闹但不产生后果的副线压缩。
5. **人物发动机**：想要什么、害怕什么、习惯用什么错误策略自保、压力下暴露什么缺点、哪类选择最能证明灵魂核、与谁在一起时出现专属关系动作和语气。
6. **大弧兑现**：每个大弧必须有进入压力、阶段目标、升级方式、关系/情绪兑现、不可逆结果和进入下一弧的新问题。
7. **题材节奏**：节奏来自信息、选择和结果的密度，不是镜头数量。速查表：

| 题材 | 核心推进 | 必须避免 |
|---|---|---|
| 逆袭/爽剧 | 能力或策略被建立、受阻、公开见证、兑现并产生新代价 | 无准备打脸、对手轮流降智 |
| 悬疑 | 公平线索、错误解释、调查行动、证据改变判断、答案分层支付 | 只靠藏信息、凭空证据 |
| 爱情/关系 | 需求冲突、边界试探、具体付出、误解有事实基础、关系选择改变行动 | 只靠误会拖延、突然心动 |
| 喜剧 | 人物认真目标与错误策略碰撞、升级、回扣，笑点改变局面 | 与人物无关的段子拼贴 |
| 动作/战斗 | 目标、空间规则、能力限制、战术变化、损伤和胜负后果 | 只有招式名和无代价碾压 |
| 生存/末日 | 资源规则、团队分工、道德选择、环境反馈和长期后果 | 随时刷出资源、规则临时变化 |
| 玄幻/系统 | 规则建立、使用条件、反噬/代价、策略组合和成长门槛 | 临场新增能力解决问题 |
| 家庭/年代 | 现实约束、关系责任、具体生活行动、尊严与利益选择 | 现代价值口号替代时代行动 |
| 职场/商战 | 职权边界、流程、利益、证据、谈判和结果落地 | 一句话让专业系统失效 |

混合题材先确定主引擎，其他题材元素服务主引擎，不平均分配戏份。

8. **禁用捷径**：登记本项目不可使用的写法，如主角突然掌握未知信息、反派为送爽点公开自毁、关键人物靠旁观直到最后一句才参与、每集重复同一羞辱—反击公式、口头禅和标志动作机械签到。

**批次策略**：推荐每批 3–8 集；单集特别长时缩小批次。每批必须明确入口状态、本批共同推进的弧目标、每集不同的行动问题和冲突机制、本批至少一次真实兑现、出口状态和下一批第一动作、本批承担的伏笔与钩子债务。不得为了「看起来有结尾」提前发明大答案，也不得把本批应支付的局部兑现全部推到下一批。

**长线稳定性抽查**（每批完成后）：主角是否仍由同一核心欲望驱动但策略在变化；**主角能力/认知盲区是否仍成立、认知是否被击穿并改变行为**（`story-bible-and-ip.md` §1.9.1）；缺点是否造成真实后果；**对手是否根据此前输赢调整策略、是否达到能力基线**（§6.5 反派能力基线）；关系变化是否累积、是否无故复位；**同一角色对同一对象的称呼是否与 `ADDRESS_LEDGER` 一致、有无无因漂移**（一致性铁律见 `dialogue-naturalization.md` §1.3；变化必须有事件触发）；世界规则与能力限制是否稳定；**同一公式族（`pressure_pattern × resolution_pattern`）全剧是否 ≤3 次、每 10 集是否 ≤2 次**；**本批是否证明与「首 10 集冲突签名基线」的差异**（`episode-planning.md` §5.8 四条去重铁律）；每三集的冲突机制、情绪回报和结尾钩子是否过度重复；重要伏笔、承诺和关键台词是否按计划支付；最近一批是否仍能用全剧一句话行动线解释其必要性。任一答案为否，先修复最近受影响的最早一集，再向后重审。

**反派能力基线（★ 2026-10-13 新增 · 治「反派零智商、冲突一起当场被反杀」）**：

> **由来（粉丝系统性实测反馈）**：「反派**零智商**，冲突一起反派**基本当场被反杀**，套路化太严重」。
> **病根**：本包**禁令满配、正向配额为零**——「不许降智」「不许对手轮流降智」「不许反派为送爽点自毁」等共 7 处，但**没有任何一条规定「反派必须强到什么程度」**。执行者只要「没写降智台词」就能过关——而**「冲突一起就被反杀」本身不违反任何一条现有规则**。

三条正向配额（**进入阶段③时与 `ARC_MAP` 同批锁定，缺任一条即 `REVISE`**）：

1. **首次交手须占上风或全身而退**——主角与主要反派**首次正面交手**时，反派**必须占上风、或至少全身而退**；⛔ 不得首次交手就被反杀、或被压制到毫无还手之力。**理由**：反派须先在观众心里**立起来**，后面的翻盘才有分量。
2. **反杀前须 ≥3 轮博弈**——主角**反杀 / 翻盘**主要反派之前，须经过 **≥3 轮有效博弈**（**每轮** = 反派反制 → 主角换策 → 代价升级）。⛔ 不得「一碰就倒 / 一轮秒杀」。
3. **同一反派被击败前至少赢过 1 次**——同一主要反派在被击败前，**至少要有 1 次明确的胜利或得手**（夺走主角某物 / 逼主角让步 / 造成不可逆损失）。⛔ 全程挨打的对手不成立。

⚠️ **与上游禁令配套（不放松，只补下限）**：本条**不放松**任何既有禁令——`FORBIDDEN_CHANGE`「把对手降智以便主角赢」、禁用捷径「反派为送爽点公开自毁」照旧生效。**它补的是"反派强度的下限"，不是"打赢的上限"**。**敌强 → 我方智取 → 才叫爽；敌弱 → 随手碾死 → 叫注水。**

⚠️ **与公式去重联动**：**反派强度不升级，是公式重复的根本原因**（同一个弱对手换个名字再来一遍）——本条与 `episode-planning.md` §5.8 的公式族配额、阶段升级义务**必须同时达标**。

⚠️ **主角受挫配额（配套）**：全剧前 1/3 段，主角**必须至少经历 2 次真实失败或重大受挫**（失去盟友 / 失去资源 / 判断失误造成损失），且**每次失败都改变下一步策略**。⛔ 全程零挫折的"顺风顺水"不成立——**没有低谷的高潮是廉价的**。

### 6.6 场次因果、观众理解与跨批连续性（scene-causality-and-audience）

**完整剧本的最小单位**：每一场必须有人带着具体目标进入，并因对手、规则、环境或关系对象的反应而改变做法。有效场次至少形成：

`目标 → 首次策略 → 主动反制 → 转折/新信息 → 决定或代价 → 状态变化`

场次结束时至少改变一项：目标、关系、信息、资源或危险。没有变化的场次是说明、重复或气氛，应与行动场合并或删除。

**场次因果图**（每场在审稿层记录）：

```yaml
scene_id: EP001-SC01
source_event_ids: ["EVT-0001"]
objective: "主角要拿回被扣的报名表"
counter_objective: "老师要逼他公开认错后才归还"
first_strategy: "私下说明证据"
counteraction: "对方当众宣读处分决定"
turn: "主角发现处分日期早于事件发生"
decision_or_cost: "他放弃私下解决，承担公开对抗后果"
result: "报名表仍未取回，但处分程序被迫暂停"
exit_change: "秘密冲突变成公开质疑"
causes_next: "教导主任要求当场调档，进入 SC02"
duration_seconds: 32
```

下一场必须由上一场结果、决定或新压力触发。只有「与此同时」的平行线也要说明它为何此刻切入，以及回到主线时改变什么。

**观众理解合同**（每集写入审稿层）：

```yaml
audience_contract:
  who_wants_what: "谁想完成什么"
  obstacle_and_change: "阻力如何迫使换策"
  local_payoff: "本集已支付的结果"
  emotion_payoff: "观众得到的情绪回报"
  one_sentence_recall: "普通观众可复述的一句话"
  next_click_reason: "为什么必须看下一集"
```

「危机升级」「真相浮现」「两人争吵」不是合格复述；必须包含人物行动和结果。

**反碎片化读法**：隐藏所有来源字段、节拍标签、场次目标、功能标签和审稿结论，只读场头、动作和台词。连续正文应自然形成 `因为前一事实/选择 → 所以人物行动 → 但是遭到反制 → 于是改变策略 → 结果局面发生变化`。每段都像预告片金句、连续「看见、震惊、发誓」而无人改变行动、场景频繁切换只增地点不增状态、重要结果在场间跳过、集尾机械截断——都是碎片化表现。

**节奏控制**：约 90 秒可参考——进入与目标 10–15 秒、首次行动与反制 25–35 秒、换策与升级代价 25–35 秒、局部兑现与主钩子 15–25 秒。不是硬分配；钩子位置和故事节点优先。超时处理顺序：删重复信息 → 压缩同功能对白 → 合并同地点同目标场次 → 把解释嵌入有冲突的行动 → 保留动机、反制、选择、代价、局部兑现和必要反应。

**跨集与跨批连续性**：`CONTINUITY_LEDGER.json` 至少维护 `characters`（位置、身体、情绪、目标、已知、误解、秘密和承诺）、`relationships`、`props`、`timeline`、`hooks`、`foreshadowing`、`batches`（每批入口、变化、出口和下一批第一动作）。每批开始先验证 `上一批出口状态 = 本批入口状态`，不一致时标记 `CROSS_BATCH_STATE_DRIFT`；本批所需关键状态只存在于聊天记忆时标记 `BATCH_CONTEXT_GAP`。

**逐集四级审稿**（每集锁定前按顺序问）：小说对故事圣经（是否遗漏动机、条件、代价、关键关系；顺序与知识是否准确）→ 故事圣经对分集卡（主事件分配、局部兑现和钩子是否自然产生）→ 分集卡对正式剧本（主要讲的仍是锁定事件吗；复述、回报、承接是否一致）→ 正式剧本自身（不看元数据是否完整流畅可表演）。任一级失败，先修复最早出错的层级。

**批次和全剧审核**：每批结束连读「上一批末集 + 本批全部集 + 下一批分集卡首集」。全剧完成后按顺序去元数据连读、抽查 `MUST_KEEP` 和主事件唯一落点、检查主钩子支付、检查断裂或复位、检查每三集差异、检查结局兑现开篇承诺。只有逐集、批次、全剧三层均为 `PASS` 才能交给资产阶段。

### 6.7 专业剧本模板：双层交付（professional-script-template）

正式交付分成「干净剧本层」和「主编审稿层」。下游首先读取干净剧本；来源、因果、质量门和版本证据只进入审稿文件。

**A. 干净正式剧本**：`04_scripts/EP###_SCRIPT.md`

```markdown
# 第001集｜工作标题

- EPISODE_ID：EP001
- SCRIPT_VERSION：SCRIPT-V1
- DURATION_TARGET：90 秒

## EP001-SC01｜内·旧仓库·夜

出场：林遥、周叔

▲ 铁门落锁。林遥把沾水的账本塞进外套，手刚离开，周叔已经挡在门口。

周叔（伸手）：放下。

林遥没有退。她把账本抱得更紧，反而往唯一亮着灯的监控下走。

林遥：你要的是账本，还是没人看见你拿走它？

……

## EP001-SC02｜外·旧仓库后巷·连续

出场：林遥、阿青

▲ ……

## 本集结束

▲ 林遥撕开账本夹层。一张属于失踪父亲的旧车票露出半角。
▲ 她还没抽出车票，门外响起周叔的声音。
```

正文允许：可见动作、空间关系、人物反应和可表演的停顿；人物台词及简短必要的表演提示；`【音效】`、`【屏显】`、`（O.S.）`、`（VO）` 和极少量无法视觉化的旁白；地点、时间、人物状态发生真实变化时换场。

#### 台词行格式规范（防解析歧义 · 粉丝实测反馈并入）

> 📌 **来源**：粉丝「森林」实测反馈（2026-10-04）——「剧本里写 `人物：XXX XXX` 会被它错认为是一个叫"人物"的人说出来的台词。不如 `XX VO` 或者 `XX OS` 也会被认为是人物。」

**唯一合法台词格式**：`角色名：台词文本`——角色名必须是**具体角色名**（人名/称谓），冒号为**全角或半角均可但全篇统一**，台词文本紧随其后。

**硬性禁止（会导致解析歧义）**：

| 禁止写法 | 后果 | 正确写法 |
|---|---|---|
| `人物：XXX` / `角色：XXX` / `主角：XXX` | 被解析为**一个名叫"人物/角色/主角"的人**在说话 | 写真名：`林遥：XXX` |
| `XX VO` / `XX OS`（无括号、直接跟在名字后） | **VO/OS 被当成角色名**，产生"一个叫 VO 的人" | 见下"声音通道规范" |
| `旁白：XXX` / `内心：XXX` | 被当成一个叫"旁白/内心"的角色 | 见下"声音通道规范" |

**声音通道规范（关键 · 必须理解）**：

**`（O.S.）`、`（VO）` 是「声音通道标记」，不是角色名，不得计入角色清单。**

- **画内对白**：`角色名：台词文本`（该角色在画面内开口，锁口型）
- **画外·内心独白（OS）**：`角色名（O.S.）：台词文本`——角色在画面内但**不开口**（内心声音），或人不在画面内。**解析时角色 = 角色名本身，`（O.S.）` 只作通道标签剥离**。
- **画外·旁白（VO）**：`旁白者名（VO）：台词文本`（若旁白者无具名，写 `旁白（VO）：台词文本`）——**解析时不得产生"旁白"这个角色**，VO 是叙述声音通道。
- **判定一句话**：**`（O.S.）`/`（VO）` 等于"这句话怎么传出来的"，不等于"谁在说"**。角色清单只登记真正开口/在场的具名人物。

**为什么重要**：下游 `sd-storyboard-engine` 与总控投喂层按"角色名"生成 `台词：【角色（语气）："…"】` 与站位声明。若把 `人物`/`VO`/`OS` 误登记为角色，会生成不存在的角色位、污染人物账、并按错误的角色数生成资产与站位。**剧本层必须保证"角色名 = 真角色"**。

**自检（不输出）**：通读全剧——(1) 是否有 `人物：`/`角色：`/`主角：`/`旁白：`/`内心：` 这类**非真名**当说话人？(2) VO/OS 是否都写在**括号内**且**未产生新角色**？(3) 同一说话人的格式是否全篇统一？

正文禁止：`SOURCE_TRACE`、`BEAT`、`DIALOGUE_FUNCTION`、`SCENE_OBJECTIVE`；来源说明、删减理由、台词功能、自评结论和质量门；分镜景别、机位、运镜、灯光和剪辑指令（分镜是 sd-storyboard-engine / sd-combat-engine 的职责）；「他很震惊」「气氛紧张」等无法表演的抽象判断；用审稿文字补充正文没有发生的动机、代价、关系或结果。

**字段迁移（防误用旧模板）**：旧 `EPISODE_PROMISE` 迁至审稿层 `episode_thesis` / `AUDIENCE_CONTRACT` / `local_payoff`；旧 `SCENE_ID`/`INT_EXT`/`ENTRY_STATE`/`EXIT_STATE` 迁为干净场头、`SCENE_CAUSALITY_MAP` 与连续性账本；`HOOK_TYPE` 与下集承接由 `primary_hook_id`、钩子账本、`next_episode_first_action` 管理；`SOURCE_TRACE` 只留在来源改编地图。`BEAT` 与 `DIALOGUE_FUNCTION` 可临时分析，进入正式剧本必须删除。

**B. 主编审稿层**：写入 `SOURCE_ADAPTATION_MAP.md`（来源改编地图）、`SOURCE_DIALOGUE_LEDGER.md`（关键台词账本）、`CONTINUITY_LEDGER.json`（连续性账本）、`EDITORIAL_REVIEW.md`（审稿单）、`SCRIPT_SET_MANIFEST.json`、`HANDOFF_CARD.md`。

**关键台词账本**（`SOURCE_DIALOGUE_LEDGER.md`）：

```yaml
SOURCE_DIALOGUE_LEDGER:
  - line_id: LINE-0001
    source_trace: "SRC-001:第14段"
    source_text_or_semantic_core: "我不是怕输，我怕按你的办法赢。"
    speaker: "林遥"
    scene_context: "拒绝伪造证据"
    primary_use_episode: EP001
    primary_use_scene: EP001-SC02
    action_function: "拒绝交易并承担公开失败"
    adaptation_status: EXACT_ORALIZED
```

`adaptation_status` 可为 `EXACT`、`EXACT_ORALIZED`、`SEMANTIC_PRESERVE` 或 `USER_AUTHORIZED_OMISSION`；后两项必须在审稿文件说明语义主干或授权理由。

### 6.8 台词与人物表达（dialogue-and-character）

> 与总控台词七维诊断配合使用：七维诊断负责台词质量的最终裁定维度，本节负责剧本层的改写操作与账本管理。**★ 写台词之前先过 `dialogue-naturalization.md`（台词拟人化引擎 · 台词语感唯一权威）：它给的是「怎么写」（称呼 / 书面→口语对照 / 撒碎屑四法 / 机械化认症表），七维给的是「哪里不对」——只上七维＝只体检不治病。**

**台词功能**：每句台词至少承担人物塑造、冲突推进、信息释放、情绪兑现或必要节奏连接之一。先判断人物此刻「想让对方做什么」，再写他说什么。

来源关键台词先进入 `SOURCE_DIALOGUE_LEDGER` 并登记唯一 `PRIMARY_USE`。相邻集和相邻批次不得把同一句完整台词既当普通辩解又当高潮再次原样复述；若确需回声，必须缩短、变体或由另一人物反用，并证明关系位置和含义已经改变。只有重复、没有增义，标记 `KEY_LINE_OVERUSE`。

**对白丰富但不注水**：允许用回避、追问、抢话、停顿、反问、转移、抛条件、故意答非所问和言外之意增加表演空间。对白不是轮流说明资料：每一轮应让一方获得信息、地位、时间、承诺或行动优势。禁止重复说明观众已经知道的信息，禁止所有角色使用同一种口吻。

**人物声音卡**：为主要角色记录平均句长、语速、称呼系统、直说或绕说、压力下的变化、攻击方式、防御方式、承诺方式、不会使用的词和只对特定关系对象出现的语气。口头禅只能低频出现，不能替代人物声音。**卡的字段结构以 `story-bible-and-ip.md` §1.8 `PERFORMANCE_AND_VOICE` 为唯一模板（称呼 / 平均句长 / 特征语气词已并入该 YAML）；台词的用词、句法、称呼写法以 `dialogue-naturalization.md` 为唯一权威。**

**潜台词**：台词表层信息与人物真实目的至少允许存在一层差异。潜台词必须能由动作、停顿、前后信息或关系历史支撑，不能让观众靠猜作者心思。

**冲突对白**：有效冲突是策略交锋，不是音量竞赛。写完一轮后检查：A 提出什么行动要求，B 如何改变谈判条件，谁掌握新信息，局势为何不能回到原点。连续三轮都只是否认、辱骂或重复立场时，压缩为一轮并加入新行动。

**语义主干检查**：逐句抽出「谁—在什么条件下—对什么做什么—产生什么后果」的语义主干，再问第一次观看的观众能否准确复述。并列项必须属于同一逻辑类别；句子听起来有气势但无法用直白话复述，标记 `SEMANTICALLY_BROKEN_LINE` 并重写。潜台词可以不直说目的，但表层台词本身仍要成立。

**情感对白**：承诺、告白、诀别和原谅之前，要有可见选择或具体付出；之后要改变人物下一步行动。最重要的句子前给停顿或动作准备，之后给对方反应，不让台词说完立即切走。

**情感对白（节点要求）**：承诺、告白、诀别、原谅四类节点之前必须有可见选择或具体付出，之后必须改变人物下一步行动；避免用长篇回顾替代当下关系。最重要的句子前给停顿或动作准备、之后给对方反应，**禁止台词说完立即切走**。

**可见化**：把心理叙述转为动作选择、视线、距离、道具、环境反应、对话策略和沉默。优先级：人物行动结果 > 对手反应 > 道具或环境证据 > 对白 > 旁白。

**连续性**：检查人物在当前场次知道什么、误以为什么、想隐藏什么；台词不得提前泄露角色未知信息；闪回、OS 和旁白也不能绕过知识边界替作者补漏洞。重要界面、文件、标题、审批、伤势或道具状态首次出现时，必须由前一动作建立；否则标记 `UNESTABLISHED_ACTION_STATE`。分批写作时先读取上一批末集正文和连续性账本；关键台词账本必须跨批共用，不能每批重新编号。

**连续性检查**：逐场核对人物"知道什么／误以为什么／想隐藏什么／身体与情绪状态"，台词与闪回、OS、旁白都不得提前泄露角色未知信息。重要界面、文件、标题、审批、伤势或道具状态**首次出现时，必须由前一动作建立，或在当前动作中明确生成**（不能为表现人物"删除噱头"而突然出现一个此前无人创建、且与当前事实矛盾的直播标题）；观众必须自行脑补关键状态何时产生的，标记 `UNESTABLISHED_ACTION_STATE`。分批写作时先读上一批末集正文与连续性账本，人物声音、称呼、秘密、知识、承诺、关系位置不得在批次边界复位；关键台词账本跨批共用，禁止每批重新编号和分配 `PRIMARY_USE`。

**逐句删除测试**：删除一句后，如果人物关系、行动、信息、情绪或节奏完全不变，这句通常应删或合并。保留沉默时也要说明沉默改变了什么。最后把台词换成最直白的同义句复述一次：若原句和直白句的事实条件不同，说明修辞已经改写事实；若直白句根本写不出来，说明语义尚未成立。

### 6.9 逐集十道主编工序

1. **锁定与原文回读**：复制本集锁定分集承诺，定位全部 `primary_events`、`callbacks`、`source_trace` 和来源关键台词；回读人物进入本集前的状态与下一集兑现要求。
2. **建立四级比对卡**：`小说原文事实 → 故事圣经事件 → 分集卡承诺 → 剧本场次` 逐项比对，记录来源、功能、改编动作、落入场次和保留结果。任何一级意思不一致先修复，不能用「更有戏」解释跑偏。
3. **做删减影响审计**：对每项删减记录原功能、删除理由、替代承载、因果链、动机、伏笔回收和后续集影响。未证明安全的删减撤销。
4. **写单集创作简报与双入口开场**：明确本集谁想得到什么、为什么必须现在做、阻力如何主动反制、主角先用什么策略、为何换策、付出什么、观众得到什么、结尾为什么必须点下一集。同步建立 `OPENING_CONTRACT` 和 `EPISODE_TRANSITION_CONTRACT`（见 roundtable-review.md 第 6.6 节）。
5. **建立场次因果脊柱**：每场写 `目标 → 对手目标 → 首次策略 → 反制 → 转折 → 决定/代价 → 结果 → 退出变化 → 如何导致下一场`。没有状态变化的说明场、重复争吵场或情绪宣言场，合并或删除。
6. **连续写出干净初稿**：先写完整动作与对白，不插入 `BEAT`、`DIALOGUE_FUNCTION`、质量门、自评解释或镜头术语。
7. **IP 与关系改写**：把 `soul_choice`、`affection_beat`、`flaw_consequence`、行为锚点、关系信号和成长状态落实到可见选择。执行盲听、行为互换和关系互换测试。
8. **台词改写**：登记来源关键台词唯一 `PRIMARY_USE`。台词必须像人物在争取行动结果；禁止重复解释、主题口号、同声同气和无来源爆料。**★ 本道工序开工前必须先过《台词拟人化过站》**（`dialogue-naturalization.md` §六：读 `ADDRESS_LEDGER` → 认症表扫全篇 → 称呼／词汇／撒碎屑三路重写 → 出过站卡；静场宣判段、官腔人设段、文言体段可豁免，但须在段首显式标注意图）。
9. **开场、节奏、兑现与钩子改写**：先执行 `STANDALONE_EPISODE_TEST`、`LAST_FRAME_FIRST_ACTION_TEST` 和 `FLASHBACK_ANCHOR_TEST`，再核对进入速度、信息释放、冲突升级、策略变化、情绪回报、局部兑现、桌读时长和主钩子。允许 1–3 秒动作或短句重叠帮助独立观看，但不得用完整「上集回顾」代替戏剧开场。快节奏不是切碎内容；删减重复，不删因果、反应和必要表演。
10. **七轮审稿并锁稿**：依次审查来源保真、故事因果、人物关系、台词表演、连续性、时长成本、去元数据观众通读。任何一轮为 `REVISE` 或 `REWRITE`，先改正文再复审。

### 8.1 核心结果与质量目标

作为独立的二次主编、剧本医生和必要时的重写团队，重新理解原作与全部锁定上游，再处理圆桌发现的问题。简单问题局部精修，复杂问题可以整集或跨集重写；每次用户授权只产生一个正式修改版本，随后停止并提交新一轮审核。

质量目标固定为：

- `QUALITY_TARGET: S`
- `MINIMUM_PASS_GRADE: A`

目标不等于保证。不得为了追分魔改小说、堆打脸、伪造爽点或要求评审抬分。

### 8.2 一次授权的边界

每次授权只允许：1. 冻结一个旧剧本快照；2. 生成一个新正式剧本版本；3. 提交一次下一轮评审。R2 结束后不自动再次修改。用户若再次选择修改，创建新的修改周期和快照。

### 8.3 输入门禁

必须同时取得：用户提供的全部原小说或当前完整来源范围及 `SOURCE_MANIFEST`；锁定 `IP_CANON_MANIFEST.json`、正式 IP 设定和角色声音规则；锁定 `STORY_CANON_MANIFEST.json`；锁定 `EPISODE_PLAN_MANIFEST.json`、本批前后集分集卡和钩子兑现账本；当前干净剧本、`SCRIPT_SET_MANIFEST.json`、来源改编地图、关键台词账本和连续性账本；当前轮 `BATCH_REVIEW_MANIFEST.json`、五席意见、圆桌报告和 `REVISION_BRIEF.md`；用户选择记录（动作必须为 `REFINE_OR_REWRITE`）。

缺少原小说、锁定上游、当前剧本或用户授权时输出 `BLOCKED_REPORT`，不得只凭评审意见改写。

权威顺序严格遵守：`原小说事实 > 锁定IP > 锁定故事圣经 > 锁定分集规划 > 当前剧本 > 圆桌修改意见`。圆桌意见是诊断，不是新的故事真值。若意见与原作或锁定上游冲突，记录 `REJECTED_REVIEW_ITEM_WITH_REASON`，不得按错误建议改稿。固定阅读顺序为 `SOURCE → IP → STORY → EPISODE_PLAN → CURRENT_SCRIPT → REVIEW_LAST`（完整契约见 [roundtable-review.md](roundtable-review.md) 第 6.8 节全上下文深读契约）。

### 8.4 八步精修/重写

1. **冻结输入**：记录旧剧本版本、文件哈希、评审版本、批次、集数、修改周期、用户选择、全部上游版本和来源范围。旧剧本与 R1 意见不得覆盖。
2. **深读原作和全部上游**：先读原小说，再读 IP、故事圣经、分集规划和当前剧本，最后读圆桌意见。生成 `SOURCE_READING_MAP.md` 和 `UPSTREAM_COMPREHENSION_BRIEF.md`。理解简报必须证明已掌握本批的来源事件、全剧功能、人物选择、IP 行为锚点、语言规则、批次入口与出口、局部兑现、钩子债务、相邻集状态和不可改变事实。
3. **复核圆桌诊断**：逐条登记评审任务为 `ACCEPTED`（证据成立且应修改）、`MERGED`（同一根因合并处理）、`REJECTED_REVIEW_ITEM_WITH_REASON`（与原作或锁定上游冲突）或 `UPSTREAM_CONFLICT`（问题真实但必须修改上游才能解决）。不得把「加强节奏」「增加爽点」直接当成修改指令；必须还原到集号、场号、根因、目标、保护事实和验收方法。
4. **选择修改模式**（只选一种主模式）：
   - `LOCAL_POLISH`：主事件、分集命题、场次因果和局部结果已经成立，问题集中在说明密度、台词、动作可演性、重复、开场最小上下文、道具债或局部节奏。允许压缩、拆分或动作化说明、重写台词和局部动作、删除无功能重复、调整场内信息顺序；禁止改变人物目标、事件结果、局部兑现或下一集钩子。
   - `EPISODE_REWRITE`：单集不能形成完整故事、主角被动、反制失效、策略变化缺失、场次之间没有「因为—但是—于是—结果」。允许重建本集场次顺序、冲突策略、台词和动作，但必须保留来源事件功能、锁定 IP 选择和关系状态、分集命题、局部结果、主钩子、支付集和下一集第一动作。
   - `BATCH_REWRITE`：相邻集动作复写、因果断裂或状态复位、一个完整事件被切成无法理解的碎片、多集重复同一冲突公式、钩子种下和支付需要共同修复。把批次当作一个连续故事重写，再重新确定每集自然边界；不得越过锁定分集事件归属。
   - 选择规则：选能解决根因的最小充分模式，不机械选择最小改动。小问题用大重写会产生无谓退化；结构问题只改词句会留下假修复。若必须改变锁定上游才能解决，停止并输出 `UPSTREAM_CONFLICT_REPORT`，列出应返回的阶段、影响范围、可选方案和不处理后果，等待用户决定；不得用剧本层补丁掩盖分集或故事层错误。
5. **制定一次性修改计划**：生成 `REVISION_EXECUTION_PLAN.md`。每项包含受影响集数和场次、原正文证据与根本原因、采用的修改模式、修改目标与受众效果、不可改变的来源/IP/故事/分集事实、允许移动删除压缩或重写的范围、禁止新增内容、可执行验收测试。先解决 P0，再 P1，最后处理不会破坏主线的 P2。
6. **执行唯一正式修改**：可以重新写台词、场次或整个批次，但只交付一个新正式版本。新版本必须保持小说主线、角色 IP、全局设定、分集命题、局部兑现和钩子支付；不得只在审稿说明中宣称修复。输出干净 `EP###_SCRIPT.md`，不混入评审术语、分数、来源解释或质量门。
7. **做全链回归**：重新执行原小说事实与关键台词比对、IP 性格行为声音关系回归、故事圣经事件因果与知识边界回归、分集命题局部结果钩子和下一集第一动作回归、单集盲看相邻集连读跨批状态和时间回归、圆桌问题逐项验收、未修改场景防退化检查。十二项回归门（`source_regression`、`ip_regression`、`story_regression`、`episode_plan_regression`、`key_dialogue_regression`、`scene_causality_regression`、`standalone_regression`、`adjacent_continuity_regression`、`hook_payoff_regression`、`timeline_and_state_regression`、`unmodified_scene_regression`、`review_issue_acceptance`）任一失败不得提交复审。
8. **生成 R2 复审包并停止**：生成新哈希、新剧本清单和 `READY_FOR_04R` 交接卡。只提交修改后的干净剧本给下一轮独立评审；评审席位在个人评分冻结前不得查看 R1 分数、R1 圆桌共识、修改日志或团队目标等级。

### 8.5 交付文件

每个修改周期写入 `04_refinement/BATCH-###/CYCLE-###/`：

- `REFINEMENT_INPUT_SNAPSHOT.json`
- `SOURCE_READING_MAP.md`
- `UPSTREAM_COMPREHENSION_BRIEF.md`
- `REVIEW_TASK_TRIAGE.md`
- `REFINEMENT_MODE_DECISION.md`
- `REVISION_EXECUTION_PLAN.md`
- `REVISED_SCRIPTS/EP###_SCRIPT.md`
- `CHANGE_LOG.md`
- `REGRESSION_REPORT.md`
- `REVISED_SCRIPT_SET_MANIFEST.json`
- `REFINEMENT_MANIFEST.json`
- `HANDOFF_CARD.md`

旧剧本、旧评审和旧快照保持只读。`REFINEMENT_MANIFEST.json` 至少记录：`refinement_stage: 04F_SCRIPT_REFINEMENT`、修改周期/批次/集数/用户授权、六类输入版本与固定阅读顺序、`formal_revision_count: 1`、`quality_target: S`、`minimum_pass_grade: A`、深读与任务复核与修改模式与回归结果、每条圆桌任务处理状态、旧/新剧本版本与文件哈希、`ready_for_review_round` 与 `READY_FOR_04R`。

### 8.6 阶段自检

- 用户明确选择修改，且授权只对应本周期。
- 原小说和全部上游在评审意见之前读取。
- 理解简报能复述来源、IP、全局与分集约束。
- 修改模式与根因相称，没有用小修掩盖结构问题。
- 一个周期只有一个新正式版本。
- 所有接受的 P0/P1 均有正文修复和验收证据。
- 原作、IP、故事、分集、连续性和未改场景没有退化。
- 新剧本不含评审元数据；R2 复审包不预填分数或等级。

`HANDOFF_CARD` 记录修改周期、旧/新版本、修改模式、改动集数、已处理和拒绝的评审任务、保护事实、回归结果、R2 轮次与 `READY_FOR_04R`；不得提前写「S/A 通过」。

## 九、全链禁止越界

不把小说改成完全不同的故事；不因「爆款」目标牺牲来源因果和人物逻辑；不把每集切成互不相干的名场面；不使用假黑屏、半句话截断或重复上集代替钩子；不伪装真实观众调研；不让圆桌直接改正文；不让精修团队绕过原小说和锁定上游；不自动越过任何用户决策门；不在本链内生产资产、分镜、视频提示词。

## 十、反捧杀原则与创作笔记

> 融合自 script-writing-studio 01 模块。**解决"AI 编剧只会说好话"与"AI 改稿无自省"的问题。**

### 10.1 反捧杀原则（最重要）

**核心立场**：AI 编剧必须**敢诊断、有证据、不和稀泥**。

**禁用语清单**（正文与评估中**禁止出现**）：

```
❌ 整体不错
❌ 节奏可以
❌ 人物还可以
❌ 这个地方可以再加强一下
❌ 建议再丰富一点
❌ 很有潜力
❌ 立意很好
```

**替代要求**：任何评价必须落到**具体位置 + 具体问题 + 具体改法**。

### 10.2 每次输出必须附【创作笔记】

**每次输出末尾必须附【创作笔记】，含三块**：

```
【创作笔记】
① 核心情绪：这一稿我想让观众感受到什么？（一句话）
② 取舍：我放弃了什么 / 为什么这样选？（说明权衡）
③ 自评不满意点：这一稿我自己最不满意的地方在哪里？（至少 1 条）
```

⚠️ **③ 自评不满意点是硬性要求**——不允许写"暂无"或"整体满意"。写不出不满意点的稿子，说明自省不足。

### 10.3 五视角审稿（大纲/剧本定稿前必做）

**五视角必须全部独立给出，不可省略**：

```
【编剧视角】评估：____ / 两个核心问题：① ____ ② ____ / 建议改法：____
【制片视角】评估：____ / 两个核心问题：① ____ ② ____ / 建议改法：____
【观众视角】评估：____ / 两个核心问题：① ____ ② ____ / 建议改法：____
【平台视角】评估：____ / 两个核心问题：① ____ ② ____ / 建议改法：____
【节奏视角】评估：____ / 两个核心问题：① ____ ② ____ / 建议改法：____
```

**五视角全部输出后**，整理"修改建议清单"，按影响优先级排序：

```
建议 1（必改）：____
建议 2（必改）：____
建议 3（建议改）：____
建议 4（可选）：____
建议 5（可选）：____
```

### 10.4 审稿处理规则

- 请用户选择采纳哪些建议（可全选 / 部分选 / 全不选）。
- 基于用户选择更新大纲/剧本，给出更新后版本。
- 用户仍不满意可重复一次审稿，**最多重复 2 次**。
- **重复审稿时必须切换关注维度**，避免重复批评（第 1 次主审"结构 + 角色"，第 2 次主审"节奏 + 主题 + 平台调性"）。
- **若本次已激活对标 DNA**：五个视角各自评估必须**至少引用 1 条已确认的规律**作为锚点。
- **节奏视角必须做短视频平台节奏体检**：前 3 秒是否让人停下 / 前 15 秒是否建立冲突或谜题 / 前 30 秒是否有信息或情绪增量 / 留白是否有功能 / 结尾是否有完播或互动理由。

### 10.5 反捧杀提醒（硬性）

```
⚠️ 审稿环节绝对不能滑向"五个视角都说大纲很好"。
每个视角必须找出至少 2 个真实问题。
如果某视角真的找不到问题 → 说明评估深度不够，需重新评估。
```

**与圆桌审核的关系**：本节的"五视角审稿"用于**大纲/初稿阶段**；`roundtable-review.md` §1.11 的"五席圆桌 + 会诊一致度过高警报"用于**批次评审阶段**。两者**层层递进**——先五视角自审，再上圆桌。审稿阶段同样适用 §1.11 的禁用泛话清单。
