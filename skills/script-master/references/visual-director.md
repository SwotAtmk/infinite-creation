## 一、功能定位

导演画面版不是重写剧情，也不是普通环境描写。

它的任务是：在不改变剧情、人物关系、台词含义和风格锁的前提下，把普通剧本转换为适合 AI 拆分镜 / AI 视频生成 / 分镜师理解的视觉连续性剧本。

导演画面版必须解决四类问题：

1. **空间连续性**：谁在画面内，谁在画面外，谁即将入场，人物站在哪里。
2. **视觉铺垫**：任何新人物、新道具、新攻击、新特效不能无铺垫突然出现。
3. **动作过程**：不能只写"两人打斗"，必须写清楚怎么打、怎么躲、打到哪里、身体怎么反应。
4. **画面张力**：剧情不能只被总结，要被具体可见的动作、环境变化、特效变化、受击反馈呈现出来。

## 三、输出原则

### 3.1 不改变剧情原则

导演画面版只能补充：

- 空间信息
- 人物站位
- 环境状态
- 即将入场人物的铺垫
- 动作过程
- 受击反馈
- 特效形态
- 场景变化
- 镜头承接
- AI 分镜避免误解提示

禁止改动：

- 剧情走向
- 人物关系
- 台词核心含义
- 伏笔状态
- 信息边界
- 已确认风格锁
- 角色生死/胜负/立场

### 3.2 风格锁遵循

导演画面版必须遵循项目档案中的语言风格锁：

- 白描：克制、短句、动作和物象优先，少形容词，不煽情。
- 浓烈：情绪外放，动作冲击强，画面可以更具戏剧性。
- 喜剧：强调反差、错位、节奏断点和可视笑点。
- 标准：平衡叙事，画面清晰，不偏向过度抒情或过度夸张。

### 3.3 视觉捕获规格锁遵循

当项目用于 AI 分镜、AI 视频生成或导演画面版时，必须同时读取项目档案中的【视觉捕获规格】🔒。它是全片统一的视觉技术基线，独立于语言风格锁。

必须继承：

- 视觉形态、全片视觉总纲、色彩和光影基线。
- 模拟摄影机或大画幅体系、镜头组、等效焦段策略。
- 画幅比例、帧率、快门或运动模糊、景深策略。
- 胶片或色彩模拟、颗粒、锐度、黑位、肤色和运镜基线。

设备品牌或格式名称不能单独作为 AI 提示，必须同时转译为可执行影像参数。例：写“IMAX 大画幅观感”时，同时写清画幅比例、广角或中焦段倾向、景深、空间尺度、帧率、快门/运动模糊和色彩策略；IMAX 不得被误写为胶片型号。

单镜仅在以下情况下记录【视觉规格偏离】：剧情明确要求梦境、回忆、监控、手机、主观视角、不同年代或特殊能力视角，且必须写明偏离原因、影响范围和回归基线的位置。没有原因不得擅自更换摄影机感、镜头组、胶片观感、画幅或调色。

### 3.4 AI 友好原则

画面版要避免 AI 误解：

- 不写抽象词替代画面，比如"气氛紧张"必须转成可见画面。
- 不让角色突然出现。
- 不让道具突然出现在手里。
- 不让场景破坏突然发生。
- 不让攻击结果没有过程。
- 不让特效只有名字没有形态。

## 四、画面版七层设计

每个画面段必须根据剧情需要覆盖以下七层。不是每层都必须单独成标题，但输出内容必须包含这些信息。

### 1. 空间层

解决"人在哪里，画面里有什么"。

必检内容：

- 地点
- 时间/光线/天气
- 场景结构
- 画面内人物
- 画面外人物
- 即将入场人物
- 人物站位
- 道具位置
- 出入口位置
- 环境状态

内部分析示例（只用于生成前检查，不得原样输出）：

```text
破庙正殿。月光从屋顶破洞斜照下来，在积水旁留下一块冷白光斑。沈舟站在佛像前，林晚靠近门口；黑衣刀客仍藏在殿外左侧廊柱后，尚未入画。断香炉横在两人之间。
```

正式正文应把上述信息拆入自然的 `△` 动作段。

### 2. 剧情层

解决"这段画面推进什么"。

必检内容：

- 本画面剧情目的
- 角色此刻目标
- 冲突点
- 本镜转折
- 下一画面承接点

### 3. 表演层

解决"人物怎么演"。

必检内容：

- 表情
- 眼神
- 呼吸
- 手部动作
- 身体重心
- 台词与身体是否同向/矛盾/替代

### 4. 动作层

解决"怎么动"。

必检内容：

- 动作起点
- 谁先动
- 攻击路径
- 防守/闪避
- 身体位移
- 动作结果
- 优势是否转移

### 5. 受击反馈层

解决"打中了哪里，身体发生什么"。

必检内容：

- 攻击落点
- 身体反应
- 衣物/护甲/皮肤变化
- 疼痛表现
- 重心变化
- 动作迟滞
- 后续影响

示例：

```markdown
刀背砸中沈舟左肩，他整个人向右侧歪了一下，左手短暂失力。
肩头衣料被割开一道口子，血没有立刻流出，只在布料边缘慢慢渗开。
他再抬刀时，左臂明显慢了半拍。
```

### 6. 特效层

解决"能力/法术/科技效果长什么样"。

必检内容：

- 特效来源
- 颜色
- 形状
- 运动轨迹
- 强度变化
- 与人物互动
- 与环境互动
- 消散方式

示例：

```markdown
刀身上的青色符纹从刀柄一路亮到刀尖，光不是均匀发亮，而是像水流一样一段段推进。
刀锋挥出时，青光在空气里拖出半弧形残影。
残影掠过地面积水，水面被气流压出一道弯曲波纹。
```

### 7. 环境变化层

解决"场景不是背景板"。

必检内容：

- 桌椅翻倒
- 门窗破裂
- 墙面被划开
- 地面积水被踩乱
- 烟尘扩散
- 光线被遮挡
- 人群反应
- 道具位置改变

### 8. 声音层（声画版扩展，仅声画版输出时启用）

解决"声音不是后期才补的"。

> 本层仅在用户触发**声画版**输出模式时启用；普通画面版不强制覆盖本层。
> **边界**：只做叙事性声音（环境声/叙事性音效/情绪声音/声画关系），不写配乐/BGM/具体音乐曲目。
> 参照库：`references/sound-design-library.md`（区1 环境声/区2 叙事性音效/区3 情绪声音/区4 声画关系/区5 通病急救/区6 联动案例）。

必检内容：

- 环境声锚点：本场至少 1 个具体环境声（如"水管滴水，间隔三秒一次"），避免"一片寂静"式空白
- 叙事性音效：承担信息功能的音效（预警/揭露/转折/记忆触发/空间转换/情绪放大），无信息的音效删除
- 情绪声音：沉默/呼吸/心跳/脚步/日常动作声，随情绪递进而变化
- 声画关系：J-cut/L-cut/声音错位/声音消失/声音对比，作为剪辑提示点明，不展开为技术参数表
- 声画同步：声音与画面动作同步，角色在跑步写脚步声+呼吸声，对话时环境声让位给台词
- 声音禁忌：禁止"背景音乐响起/配乐转为激昂/BGM 渐强"等后期制作范畴内容

声画版写作要点（声音元素自然融入 `△` 描写，不单列表格）：

- 环境声写在建立空间的 `△` 段中，与光线/天气/人物站位同段自然出现
- 叙事性音效写在动作 `△` 段中，作为动作的伴随或前导（如声音先入 J-cut，音效先于画面出现）
- 情绪声音写在表演 `△` 段中，与表情/呼吸/手部动作同段（如"她没说话，只有呼吸声越来越重"）
- 声画关系用一句话点明，不展开（如"`△`画面切黑，但水管滴水的声音延续到下一场"——L-cut 提示）
- 沉默用环境声反衬，不写"一片沉默"，写"只剩水管滴水声"

## 五、出场连续性锁

### 5.1 核心规则

任何人物、怪物、道具、攻击、特效，不能在画面中无铺垫突然出现。

如果下一画面出现新元素，上一画面或更早画面必须至少提供一种铺垫。

### 5.2 铺垫方式

1. 视觉铺垫：远处身影 / 阴影 / 轮廓 / 衣角 / 武器一角。
2. 声音铺垫：脚步声 / 呼吸声 / 兵器声 / 怪物低吼。
3. 环境铺垫：门帘晃动 / 水面波纹 / 烛火被风压弯 / 灰尘落下。
4. 反应铺垫：角色突然回头 / 眼神变了 / 手握紧兵器。
5. 道具铺垫：先出现来者的刀、铃铛、影子、脚印、血迹。

### 5.3 检查表

```markdown
【出场连续性检查】
□ 本画面新增人物/怪物/道具：____
□ 是否在前一画面或更早画面铺垫：是/否
□ 铺垫方式：视觉/声音/环境/反应/道具
□ 如未铺垫：必须补一条前置画面描写
```

## 六、动作导演模块

### 6.1 打戏不能写结果，必须写过程

禁止：

```markdown
两人大战三十回合，男主击败敌人。
```

必须写：

```markdown
敌人先以短刀抢中线，刀尖直刺男主胸口。
男主没有后退，而是侧身让刀锋擦过衣襟，右手扣住敌人手腕。
敌人顺势屈肘撞向男主下颌，男主被迫松手，后退时脚跟踢到碎瓦。
敌人抓住这一瞬间压上，第二刀从下往上挑。
```

### 6.2 打戏每个动作段必须交代 6 件事

```markdown
动作起点：谁先动，为什么动
攻击路径：从哪里打到哪里
防守反应：对方怎么挡/躲/吃招
受击反馈：打中哪里，身体怎么变
环境互动：撞到什么/破坏什么/扬起什么
节奏变化：优势是否转移
```

### 6.3 打戏必须有优势转移

没有优势转移，就没有张力。

常用结构：

```markdown
第一段：主角占优
第二段：敌人抓住主角弱点反压
第三段：主角利用环境反转
第四段：敌人释放底牌
第五段：主角付出代价取胜
```

### 6.4 受击反馈不能缺失

每次明确命中的攻击都必须有受击反馈：

- 打中部位
- 身体反应
- 疼痛/失衡/迟滞
- 对下一动作的影响

## 七、特效设计模块

### 7.1 特效不能只有名字

禁止：

```markdown
男主释放剑气。
```

必须写：

```markdown
男主抬刀时，刀身先亮起一线青光，随后光线沿着刀刃扩散。
他挥刀的一瞬间，青光被甩成半月形，贴着地面向前掠去。
地面积水被压出两道波纹，青光撞上黑雾后停了一瞬，才从黑雾内部裂开。
```

### 7.2 特效必须交代 5 件事

```markdown
来源：从哪里发出
形态：像什么，颜色/纹理/边缘状态
轨迹：怎么移动
互动：碰到人物/道具/环境后发生什么
消散：怎么消失或残留什么痕迹
```

## 八、输出格式

### 8.1 正文格式：标准剧本自然融合版

导演画面版首先必须是一份人能顺畅阅读的标准剧本。保留原剧本的集名、集首钩子、场次头、人物表、`△` 动作段和角色对白；空间、站位、出入场铺垫、表演、动作、受击、特效、环境变化和镜头承接自然写进 `△` 动作段，不得把七层检查维度直接显示成工程字段。

```markdown
# 第X集《集名》

## 集首钩子
△以连续可见的动作和环境变化写钩子；需要时自然交代人物位置、威胁来源和下一画面承接。

## 1-1 场景名 日/夜 内/外
人物：角色A 角色B 角色C

△先建立空间、光线、天气、人物站位和关键道具。只写当前画面能看见或听见的内容。

角色A：对白。

△角色动作与表演。下一人物或危险即将入场时，通过远景轮廓、声音、影子、环境反应、他人视线或道具变化提前铺垫。

角色B：对白。

△动作戏写清谁先动、攻击从哪里到哪里、对方怎样挡或躲、击中部位、身体反馈、环境破坏和优势变化。特效写清来源、形态、颜色、轨迹、与人物及环境的互动和消散。
```

正文融合规则：

1. 每个 `△` 只承担一个连续可见的动作单位；动作、视线、声音或环境变化发生明显转折时另起一段。
2. 人物位置、画面内外关系和道具来源融入动作，不写成“人物站位：____”等参数表。
3. 打戏与特效直接写进剧情动作，不另设“攻击路径”“受击反馈”“特效设计”等标题。
4. 视觉捕获规格锁写在文档头部的【制作基线】中，不在每个动作段重复；只有发生获准偏离时才在对应场次后说明。
5. 不为凑画面信息破坏节奏。静态文戏用关键动作、视线、距离、遮挡和环境反应维持可视性，不堆砌布景清单。
6. 原台词完整保留；只有用户要求同步修订台词时，才回到相应写作阶段处理。
7. **声画版扩展**（仅当用户触发声画版时）：声音元素（环境声/叙事性音效/情绪声音/声画关系）自然融入对应 `△` 段——环境声融入空间建立段、叙事性音效融入动作段、情绪声音融入表演段、声画关系用一句话点明。**禁止**写配乐/BGM/具体音乐曲目（后期制作范畴）。禁止把声音元素单列为"声音设计：____"参数表。沉默用环境声反衬，不写"一片沉默"。参照 `references/sound-design-library.md` 区1-区5。

### 8.2 文档头部制作基线

制作基线放在剧本正文之前，只出现一次；读者可以跳过，不影响正文阅读。

```markdown
【制作基线】
源剧本版本：____
转换范围：____
版本状态：有效 / 待复核
输出模式：画面版 / 声画版
视觉总纲：____
模拟摄影机 / 大画幅体系：____
镜头组与等效焦段策略：____
画幅 / 帧率 / 快门或运动模糊：____
景深与胶片 / 色彩模拟：____
光色、颗粒、锐度与黑位策略：____
运镜基线与禁忌：____
声音基线（仅声画版）：全片环境声基调____ / 情绪声音锚点偏好____ / 声画关系策略____ / 声音禁忌：不写配乐/BGM/具体曲目
```

### 8.3 复杂场面可选执行备注

只有多人调度、复杂打戏、大型特效或跨场连续性无法仅靠正文稳定传递时，才在该场末尾追加简短备注。普通文戏不输出。

```markdown
画面执行备注：本场____始终位于____；____只以声音/轮廓/影子铺垫，不提前揭示；关键道具____从____移动到____；视觉规格偏离____，于____恢复基线。
```

备注必须是自然语言短段，不得恢复为七层表格。

### 8.4 AI 分镜参数附件

摄影机、焦段、画幅、帧率、快门、景深、光色和避免误解等技术参数不混入剧本正文。用户明确要求“AI 分镜参数”“视频提示词”或制作系统需要结构化输入时，才在正文之后输出独立附件：

```markdown
# AI 分镜参数附件

## 1-1
- 画面范围：____
- 相机 / 虚拟相机：____
- 镜头或等效焦段：____
- 画幅 / 帧率 / 快门或运动模糊：____
- 景深与光色状态：____
- 视觉规格偏离：无 / ____
- 连续性与避免误解：____
```

### 8.5 内部检查不进入正文

七层画面设计、出场连续性锁和以下检查项由总控在内部执行，不在导演画面版正文中显示：

- 新人物、新道具、新攻击和新特效是否有铺垫。
- 人物位置、道具、光线、天气和环境是否连续。
- 动作过程、受击反馈、特效轨迹和场景变化是否明确。
- 是否符合视觉捕获规格锁，是否存在未经批准的偏离。
- 画面重点是否服务剧情，是否出现概括代替画面的情况。

如发现问题，先修正画面版；涉及主剧情、信息时点、伏笔、动机或规则时，按第九部分回流。只有用户明确要求“查看检查报告”时，才单独输出检查结果。

### 8.6 对外版本

给甲方、分镜师或 AI 视频团队时，仍使用 8.1 的标准剧本自然融合格式。删除【制作基线】中的内部版本状态、待补材料和系统术语；根据接收对象决定是否保留设备与镜头规格。不得另造“视觉执行稿”参数表破坏阅读。

## 九、连续性与修订边界

1. 普通剧本中已明确的场景、站位、出入口、道具位置和人物移动关系为事实源；本版只能补足未定义细节，不得与其冲突。
2. 不改变观众获知信息时点的纯执行补充，可直接写入画面版。
3. 会改变信息时点、伏笔强度、角色动机或胜负因果的内容，标为【需主剧本修订】，不得在画面版补写。
4. 人物、道具、动作或规则与主剧本存在硬冲突时，停止该范围转换，回到 S6；主剧本更新后重新生成对应画面版。
5. 源剧本经 S6 或 S8 更新，或视觉捕获规格锁被解锁/更换后，关联画面版自动标记为【待复核】；未经用户确认更新不影响本范围，不得继续作为制作依据。
6. 工作区文件或上下文缺失时，仅转换当前剧本可直接确定的信息；涉及跨场出入、能力规则、人物状态或伏笔承接的部分标为【待补材料】，不得补设定。用户确认“按当前片段独立处理”后，方可输出局部版。

## 十、禁止事项

- 禁止凭空增加剧情。
- 禁止改变人物关系。
- 禁止改变台词含义。
- 禁止为了画面好看而改剧情。
- 禁止让角色无铺垫突然出现。
- 禁止让攻击无过程直接出现结果。
- 禁止让特效只有名称没有形态。
- 禁止让场景变化无原因。
- 禁止将七层检查维度、内部检查表或 AI 分镜技术参数直接混入标准剧本正文。
- 禁止在声画版中写配乐/BGM/具体音乐曲目（后期制作范畴，非剧本该做）。
- 禁止把声音元素单列为"声音设计：____"参数表（应自然融入△描写）。

---

## 十一、与交付模式的关系

导演画面版默认不是甲方交付文档。

用户明确要求给分镜师、给 AI 视频团队、交付画面版、项目剧本用画面版或给甲方也看画面版时，仍输出标准剧本自然融合版；按接收对象保留必要的制作基线，可选附加 AI 分镜参数附件。

否则交付模式仍输出干净的【项目介绍】和【项目剧本】；二者不包含制作基线、内部检查结果或 AI 分镜参数附件。
