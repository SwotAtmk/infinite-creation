# ic-writer — 让 AI 编程工具把内容写进 infinite-creation

这个目录是一个 **Agent 技能（skill）**：装到本机 AI 编程工具（Claude Code、opencode、Codex、Trae 等）的技能目录后，你只要说「把这本小说写进项目」，它就会通过 HTTP API 把**文字内容**写进一个正在运行的 infinite-creation 实例。

- **`SKILL.md`** —— 给 **Agent** 读的完整契约：铁律、端点速查、字段白名单、回滚用法。工具加载技能时读的是它。
- **本文件** —— 给 **人** 读的说明：怎么装、怎么用、能做什么、有哪些坑。

## 装

在**项目根目录**执行（只是复制文件到你的用户主目录，不改动项目本身）：

```bash
pnpm run install:ic-writer        # → ~/.agents/skills/ic-writer/
# 想装到别处：
node scripts/install-writer-skill.mjs --target <你的技能目录>
```

装完**重启一下 AI 工具**——新技能要重启会话才会被发现。

## 用

前提：项目实例正在运行。在项目根目录 `pnpm run dev`（Studio，API 4610）或 `pnpm run dev:classic`（经典界面，API 4600）；技能默认地址 <http://127.0.0.1:4600>，Studio 下用 `IC_BASE_URL=http://127.0.0.1:4610` 覆盖。

然后对 AI 工具说人话就行，例如：

- 「把这本小说写进 infinite-creation，一章一段」
- 「给这个项目写 3 章剧本」
- 「把第 2 章的分镜表重写一遍」
- 「改一下人物圣经里男主的性格」

它自己会按「先读现状 → 写入 → 回读核对」走，最后给你一份可回滚的批次号。

## 能写 / 不能写

| | |
|---|---|
| ✅ 能写 | 项目属性；小说原文（一章一段）；剧本；分镜（台词 / 画面 / 镜头 / 时长 / 提示词 / 素材绑定）；人物圣经 / 风格 / 连续性；素材提示词 |
| ✅ 能改 | 上面这些**已经生成过**的内容（整段覆盖，或逐条改） |
| ❌ 不能写 | `status`、`video_path`、`video_prompt_used`、`prompt_id`、`seed` 这类「生成结果」字段——接口直接拒，防止伪造「已生成」 |
| ❌ 不触发 | 生图 / 生视频 / 配音 / 配乐 / 导出成片（`/run`、`/stages`、`/regenerate`、`/music`、`/export`） |
| ❌ 不提供 | 删除项目（没有任何这样的接口；回滚也拒绝回滚「项目创建」） |

## 要紧的限制

- **只对本机用**：实例**零鉴权**。`config.json` 的 `server.host` 保持 `127.0.0.1`；改成 `0.0.0.0` 就等于把「能读全文、能改内容、能回滚」的入口开到局域网上。
- **任务运行中先别写**：`GET /api/projects/:id` 的 `status` 为 `running` 时，删除类写入会被直接拒（409）；内容类写入可能被任务用旧数据覆盖，最后成片与分镜表对不上。
- **只走 HTTP API**：不直连 `data/ic.db`（**只读也不行**），不手改 `data/` 下的文件与 `config.json`——绕过去就没有变更日志，写错了回滚不了，来源与批次也记不上。
- **业务校验**：时长 1~15 秒；台词字数 ≤ 时长 × 5.5；单个分镜说话人 ≤ 2；分辨率 / 宽高比走固定枚举；整章写分镜单次 ≤500 条。
- **长文本走文件**：正文别内联进命令行（Windows 的 `cmd.exe` 会把裸换行当成命令结束、静默截断），用 JSON 文件传。
- **回滚只恢复数据库内容**：磁盘上的图片 / 视频文件不会跟着删，要重传。
- **每一步都能回滚**：一次调用 = 一个批次，可单条、整批（`batch_id`）或按时间点回滚；变更之后又被改过时接口回 409（漂移保护），确认要覆盖才加 `force:true`。
