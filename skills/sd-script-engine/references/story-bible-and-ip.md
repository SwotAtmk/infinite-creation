# 上篇 · 阶段② IP 与角色开发

## 1.1 门禁与输入

只读取已登记锁定的阶段①。`STEPWISE` 完成后置为 `AWAITING_CONFIRMATION`，用户确认前禁止阶段③；`FULL_SCRIPT_PIPELINE` 只有通过阶段②校验清单后才能内部锁定并继续。不输出故事圣经、分集或剧本。

读取 `PROJECT_PROFILE`、`SOURCE_MANIFEST`、全部已提供原文、事实账本和用户视觉硬约束。先按 [source-registration.md](source-registration.md) 第二节完成 P1/P2 角色事实扫描；没有完成全部已提供来源覆盖时，只能输出 `PARTIAL_DRAFT`，不得锁定人物终局、伤口、关系或成长弧。

本规则面向所有小说和剧本题材。测试材料只用于验证方法，不得把其中的人名、职业、道具、关系、冲突结构或美术答案写入通用规则。

## 1.2 开发顺序

1. 扫描全篇角色证据，区分作者说明、人物自述、他人评价、重复行为、关键选择和真实后果。
2. 建立 `AUDIENCE_GENRE_CONTRACT` 与 S/A/B/C 角色层级；只深做 S/A，必要的长期 B 角色做轻量档案。
3. 为每个核心角色建立 `SOUL_ENGINE`：想要、需要、恐惧、错误信念、自保缺陷、底线、重复选择和最终选择题。
4. 建立 `AUDIENCE_AFFECTION_MODEL`：注意、敬佩、共情、反差喜爱、失望风险与重新赢回观众的行动。
5. 建立 `MEMORY_ANCHOR_SYSTEM`：灵魂、行为、语言、视觉、关系五类记忆点；每项必须有意义、首次使用、变化、兑现和防滥用规则。
6. 建立关系专属行为、可表演动作、微表情、台词节奏、音色词和 `CHARACTER_EVOLUTION_MAP`。
7. 完成 `VISUAL_IDENTITY_SYSTEM`、基础 `CHAR`、必要 `LOOK`、风格选择和生成一致性约束。
8. 执行换名、剪影、盲听台词、角色互换、关系互换、缺陷代价与长期成长测试；失败就返修，不用形容词补洞。

## 1.3 项目承诺卡

```yaml
AUDIENCE_PROMISE:
  target_audience: "主要观众与观看情境"
  genre_contract: "题材必须持续提供的体验"
  emotional_core: "观众最终为哪段情感留下"
  one_line_hook: "人物 + 异常处境 + 目标 + 最大阻力"
  innovation_point: "相对常见套路真正改变玩法的一点"
  long_running_engine: "什么矛盾能反复升级但不重复"
  expected_payoffs:
    - "能力或身份兑现"
    - "关系或情感兑现"
    - "谜团或世界规则兑现"
  forbidden_drift: "一旦发生就破坏受众承诺的写法"
  source_trace: ["source_id:range"]
```

一句话卖点必须同时包含「谁、遇到什么异常、要做什么、失败会失去什么」。创新点不能只写「更爽、更燃」，要说明新机制如何改变人物的行动选择。

## 1.4 角色灵魂卡与 SOUL_ENGINE

把「人物好看、有个性」转换为能连续制造选择、冲突和记忆点的 IP 设计。所有事实保留来源；没有证据的设计必须标记 `INFERENCE`、`ASSUMPTION` 或 `OPEN_ITEM`。

每个主要角色填写一张；主角、核心对手和核心关系对象不可缺项。

```yaml
CHARACTER_CORE:
  character_key: "本剧本改编包使用的稳定角色键；本引擎不建立正式资产ID"
  story_role: "主角/对手/盟友/关系对象/催化者/见证者"
  dramatic_job: "这个角色在故事里持续制造或解决什么问题"
  SOUL: "当欲望和代价冲突时，他反复选择什么"
  SOUL_ENGINE:
    want: "自认为想得到的具体结果"
    need: "必须学会却尚未承认的东西"
    fear: "最害怕失去、暴露或重演什么"
    false_belief: "由恐惧推导出的错误信念"
    flaw_strategy: "用于自保却制造新问题的策略"
    moral_line: "不愿跨越的边界"
    choice_pattern: "受压时可预测的取舍规律"
    arc_question: "最终必须以行动回答的问题"
  visible_evidence: "来源中能证明 SOUL 的动作或选择"
  wound: "塑造当前策略的既往事件；无证据不得虚构"
  choice_cost: "坚持目标会伤害什么"
  secret: "主动隐藏的事实"
  knowledge_boundary: "当前知道/误以为/不知道什么"
  relation_engine: "他需要对方什么，又拒绝承认什么"
  source_trace: ["EVT-####", "source_id:range"]
```

`SOUL` 用选择表达，例如「被误解时仍先保护弱者」，不要写「善良正直」。核心对手也需要合理目标、有效策略和可理解代价；不能只承担辱骂与送人头功能。缺陷必须至少造成一次机会、资源、关系、身份或道德代价。只有「路痴、不会做饭、爱睡觉」而不影响选择时，属于萌点，不是人物缺陷。

## 1.5 观众喜爱路径 AUDIENCE_AFFECTION_MODEL

每个 S/A 角色分别设计，不能只写「讨喜」。喜爱不是一次性标签，而是「注意—理解—敬佩/心疼—失望风险—行动修复」的过程。

```yaml
AUDIENCE_AFFECTION_MODEL:
  attention_entry: "观众第一次为什么停下来看"
  admiration_basis: "哪种能力、价值或行动值得敬佩"
  empathy_wound: "观众何时理解其痛苦；无来源写 OPEN_ITEM"
  lovable_contradiction: "外在策略与真实需要之间的反差"
  disappointment_risk: "缺陷如何真实伤害目标或关系"
  recovery_choice: "靠什么有代价的行动重新赢回观众"
```

角色的主要喜爱入口可来自能力、价值、脆弱、反差、幽默、关系投射或陪伴感。每个角色选择一项主要入口、一项辅助入口；禁止全员都靠悲惨身世、身份碾压或嘴硬心软。只有优点没有缺点后果会变成纸片偶像；只有创伤没有主动选择会变成被动受害者。

## 1.6 关系引擎矩阵

| 关系对 | A 想从 B 得到 | B 想从 A 得到 | 表面联盟 | 隐性冲突 | 不可说出口的话 | 可升级事件 | 最终选择 |
|---|---|---|---|---|---|---|---|
| A ↔ B | 具体需求 | 具体需求 | 当前共同目标 | 利益/价值/秘密冲突 | 潜台词来源 | 能改变关系状态的行为 | 尚待回答的问题 |

有效关系必须是双向的。若删除 B 后 A 的行动完全不变，B 可能只是工具人；若两个人目标、语气和解决问题方式相同，应合并职责或重设差异。

核心关系至少包含：互相需要、互相拒绝承认的需要、隐性冲突、独有相处动作、破裂信号、修复信号和最终选择。把关系对象互换后对白和动作仍成立，标记 `RELATIONSHIP_SWAP_PASS`。关系不是替人物「提供温柔的一面」；不同对象必须触发不同的控制权、距离、称呼、保护方式和脆弱程度。

## 1.7 五类记忆点 MEMORY_ANCHOR_SYSTEM

1. **灵魂记忆点**：观众从一次选择认出价值内核；重复出现但代价逐步升级的价值选择。
2. **行为记忆点**：压力下会重复出现、又能随成长发生变化的动作策略；可拍、可变化。
3. **语言记忆点**：句长、速度、称呼、回避方式、攻击方式和承诺方式；不是机械口头禅。
4. **视觉记忆点**：轮廓、主色、材质、发型或随身物，最多三项主锚点。
5. **关系记忆点**：人物只在特定对象面前出现的距离、视线、称呼或保护动作。

每个记忆点填写 `meaning`、`first_use`、`variation`、`payoff` 和 `do_not_overuse`。视觉物件若不能体现身份、情绪、时代或剧情功能，应删除。同一集通常只突出一至两个主记忆点；其余保持自然存在。机械重复动作或口头禅标记 `STATIC_SIGNATURE`。

## 1.8 可表演与声音卡 PERFORMANCE_AND_VOICE

```yaml
PERFORMANCE_AND_VOICE:
  neutral_posture: "静止时重心、肩颈、视线"
  pressure_tells: ["呼吸变化", "手部小动作", "距离变化"]
  anger_mode: "爆发/压低/回避/讥讽，以及可见动作"
  intimacy_mode: "只对信任对象出现的行为"
  speech_length: "短句/完整句/长句的使用条件"
  tempo: "常态语速与压力变化"
  VOICE: "年龄感、音域、气息、速度、力度、抑扬"
  banned_expression: ["不符合身份的说法", "禁止的声音模仿"]
  # ★ 以下三项 2026-10-13 新增 —— 使阶段③建的卡在阶段⑤《台词拟人化过站》真正可用
  #（此前 §6.8 要求记录"称呼系统"，本 YAML 却无该字段 → 阶段间断链，是台词写出机械腔的结构性成因之一）
  address_system:
    - target: "对谁的称呼（同一角色对多个对象各列一条）"
      relation_stage: "当前关系阶段（初识 / 熟识 / 亲密 / 决裂 / 旧情）"
      address: "本阶段实际使用的称呼"
      forbidden: ["本阶段绝不该出现的称呼（防称呼穿越）"]
  avg_line_length: "常态平均句长（字）—— 供过站做「句长方差测试」"
  signature_particles: ["该角色专属语气词 / 口头禅，3~5 个 —— 供「遮挡名测试」"]
```

分别写常态、受压、亲密、愤怒和崩溃后的重组状态。动作必须包含准备、变化和对手反应，不能只写「眼神复杂」。声音用年龄感、音域、气息、语速、力度、停顿和抑扬描述，不指定现实演员或未经授权的真实人物声音复刻。**称呼系统与语言指纹（特征语气词 / 专属用词）的写法细则见 `dialogue-naturalization.md`（台词拟人化引擎 · 台词语感唯一权威）——本 YAML 是唯一卡模板，那份是唯一写法权威。**

角色语言与视觉应互相支持：习惯控制局面的人可以动作极少、句子先给结论；善于伪装的人可能外形秩序严密、台词却频繁替换主语。不要把所有强者都设计成黑衣、低音、短句和冷脸。

## 1.9 成长地图与长期生命力

```yaml
CHARACTER_EVOLUTION_MAP:
  stable_core: "始终不变、决定角色身份的价值核"
  ability_start: "开局的能力层级 + 能力盲区（他会什么、不会什么）★ 必填"
  cognition_start: "开局的认知盲区（他确信、但实际是错的判断）★ 必填"
  start_state: "开篇采用的旧生存策略"
  fracture_state: "旧策略造成不可忽略后果的阶段"
  growth_state: "尝试新选择但仍会反复的阶段"
  end_state: "用新策略回答核心选择题的状态"
```

长期化不是冻结人物。稳定的是价值核和识别逻辑，变化的是应对压力的策略、关系表达、锚点含义和能力边界。每一次成长都要保留旧痕迹并支付代价，不能一集顿悟后永久无缺点。行为、语言、视觉和关系记忆点都要有成长变体：角色成长后可以不再攥紧某个物件，但可把同一物件主动交给别人；符号仍在，意义改变。

### 1.9.1 能力与认知起点（★ 2026-10-13 新增 · 治「主角开局满级、零认知转变」）

> **由来（粉丝系统性实测反馈）**：「人物弧光：**主角基本全是满级，零认知转变**！配角基本全是工具人，全程零智商」。
> **病根**：`start_state` 写的是「开篇采用的旧生存策略」（偏"错误策略"），**不是"能力层级"**——于是"主角一开局就很能打 / 很会算 / 自带金手指"**完全不违规**。全包搜不到任何一条「主角开局必须存在能力或认知盲区」的规定。

三条硬约束（**进入阶段③故事圣经时逐条填写，缺失即 `REVISE`**）：

1. **`ability_start` 必填**——写明开局的能力层级 + **能力盲区**（他会什么、**不会什么**）。⛔ **不得全员满级**：主角开局必须存在**可测量的能力缺口**，且该缺口在全剧中**至少造成 1 次真实损失**（呼应 §1.9「每一次成长都要保留旧痕迹并支付代价」）。
2. **`cognition_start` 必填**——写明开局的**认知盲区**：他**确信、但实际是错**的判断（关于世界规则 / 关于某个人 / 关于自己）。⛔ **不得开局全知**：整部剧**至少一次**让这个盲区被事实击穿，并**迫使行为改变**。
3. **认知转变必须落在行动上**——逐集 `growth_state` 四态（`BEFORE_BREAK`/`UNDER_PRESSURE`/`PARTIAL_SHIFT`/`NEW_CHOICE`）**不得连续 ≥3 集停留在同一态**；转变必须通过**选择和后果**体现，⛔ 不得只用旁白宣布或称呼变化顶替（呼应 `episode-planning.md` §5.9）。

**金手指类设定（重生 / 系统 / 穿越 / 天生神体）不豁免**：主角可以强，但**强的部分必须写明代价或限制**。直接对位 IP 退回条件——「**主角只依赖外挂或身份，自己没有选择与代价**」→ **IP 退回**（见 §IP 质量门）。

**配角侧同步（治"工具人"）**：核心配角至少各有一项**独立于主角的目标**与**一次改变战局的自主行动**；⛔ 删除后主角行动完全不变的角色（§1.6 工具人判据）不得占用核心配角名额，降为功能角色。

**长期运营**：`IP_LONGEVITY_EXTENSION` 只从角色内核推导——情绪名场面、关系名场面、日常反差、角色短片、表情表达、海报符号和周边图案。不得先为周边强加宠物、武器、饰品和口头禅，也不得让运营提案反向成为主线事实。长期可用的角色应同时经得住主线高潮、关系戏、失败、权力变化和普通日常；只能在一种爽点场景成立的角色，不具备长期生命力。

## 1.10 IP 设计规则：CHAR / LOOK / VOICE

- `CHAR`：不轻易变化的脸、发、年龄感、体态、身高关系、基础服装结构和个人符号。
- `LOOK`：由剧情支付、跨场景持续或高频复用的服装、伤势、身份和阶段状态。
- 短暂表情、单镜动作、临时污渍不建立新 `LOOK`。
- 年龄、伤势、贫富、职业和时代变化必须有来源或显式假设。
- 每个主要角色优先一个行为记忆点、一个语言记忆点和一组视觉锚点；视觉锚点服务身份、时代和情绪，不添加与剧情无关的复杂装饰。

## 1.11 视觉身份与 IP 包装

视觉目标不是「细节很多」，而是在不同镜头、服装和情绪状态下仍能稳定识别，并且每项设计都能解释人物、时代或剧情功能。

### ★ WORLD_ANCHOR_CARD · 世界锚卡（2026-10-12 新增 · 阶段③ 强制产出）

> **由来（粉丝群实测反馈）**：「剧本大纲明确了 2035 年南京，剧本名字就是外卖员，世界观第一句就是『全链智能』AI 系统上线，
> **他出来的是 80 年代的破街烂车，人物也搞得像个协警，和外卖员的特征没有关系**。」
> **病根**：世界观设定此前只活在散文里——**没有被登记成一张卡、没有写进 HANDOFF 禁改项、也没有机检**，
> 于是到 P2 资产 / P3 分镜 / P4 投喂一路漂到模型自己的默认年代与默认人像。
> **本卡是「剧本层 → 资产层」的锚点交接单**：它不改故事，只把"这是哪个年代、这个世界什么样、什么绝对不能出现"钉死。

阶段③ 交付 `02_story/` 时**必须**附一份世界锚卡（并抄进 `HANDOFF_CARD.md` 禁改项，随稿传到 `sd-asset-engine`）：

```
【世界锚卡 WORLD_ANCHOR_CARD】
  年份/朝代：2035 年（精确到年；架空须写「架空·科技水平≈20XX」）
  地域：南京·城西高架桥下（精确到市/区/场所）
  技术时代：近未来·全链智能 AI 已上线（写明"哪项技术已普及、哪项还没有"）
  社会形态：（外卖骑手/协警/企业/平台的从属关系与收入结构）
  视觉基调：（材质/光源/色调/密度，主色 3 项）
  载具与器物：（该年代真实存在的车、箱、服、械——**只写该年代有的**）
  ⛔ 禁用元素清单：（**与本年代矛盾的元素逐条列出**，如：马车/青砖/煤油灯/
                   旗袍/木质楼梯/手摇电话/蒸汽机车）
  ✅ 必现元素清单：（该年代的"一眼认得出年代"的 3~5 个锚，如：全息广告牌/
                   无人机航道/湿沥青反光/充电桩）
  判定句：任何一镜若不含"必现元素"中的任意一项，须在镜行内复述本卡年代锚
```

**七条铁律**：
1. **只写年代锚不够**——必须同时给「禁用清单 + 必现清单」，否则模型只会回避、不会主动落到该年代。
2. **年份要精确到年**；架空必须声明技术锚（"架空·科技水平≈1998"），禁只写"未来"。
3. **禁用清单是硬项**：由模型高概率幻觉出的、与本年代矛盾的元素逐条写死（如古风题材必禁「玻璃幕墙/电线杆/运动鞋/智能手机/二维码」；近未来题材必禁「马车/青砖/煤油灯/旗袍/竹简/文言」）。
4. **本卡随 HANDOFF 传到资产层**：`sd-asset-engine` 的场景图、道具图、角色服装**必须逐项对这张卡**；对不上的不进图。
5. **改卡即改下游**：本卡变更 → `STORY_CANON_MANIFEST.json` 标记 `STALE` → 资产/分镜/投喂稿逐级重出。
6. **与赛博/古装等题材适配器的优先级**：本卡 > `presets-library.md` 通用场景预设；预设库只提供镜头语言，不提供年代。
7. **机检兜底**：出稿机检 **C26a**（世界锚缺失）/ **C26b**（年代锚与正文物证冲突）——见 `scripts/validate_prompt.py` 与 `sd-qc-engine/references/machine-check-manual.md`。

> **由来（同上反馈）**：「**人物年龄，人物身材比例都卡不到**」「人物也搞得像个协警，和外卖员的特征没有关系」。

阶段③ 交付 `02_story/` 时，**每个 S/A 级角色必须**附人物锚卡（同样抄进 `HANDOFF_CARD.md` 禁改项）：

```
【人物锚卡 @CHR-xxx】
  年龄段：28~32 岁（必写；禁只写"青年"了事，须可换算）
  性别：男（必写·禁只写身份代称）
  身高/体型：178cm·精瘦（肩宽/腰胯比/上下身比例——**必须有数字或明确体型词**）
  体态与气质：（长期职业塑造出来的身体习惯，如"常年骑车导致含胸驼背、右肩低")
  职业与社会角色：外卖骑手（平台/隶属/工号制）
  **身份外观三件套**：
     ① 职业标识物：（外卖箱/工牌/骑手服反光条/保温箱——至少 1 个可入画的硬标识）
     ② 服装形制与材质：（橙色冲锋衣·尼龙·磨白袖口·工装裤·沾泥）
     ③ 气质体态写进动作：（见人不说话、把箱子往腿边一靠的熟稳劲）
```

**四条铁律**：
1. **身份必须落到可画要素**——只写"外卖员"不算数，必须有**标识物 + 服装形制 + 气质体态**三项（缺一项，模型就会给泛化的邻近职业形象，最典型就是"外卖员→协警"）。
2. **年龄与体型必须有可复述的值**——年龄段 + 身高体型，禁止"中年男性""高大"这类不可复述的概括。
3. **⛔ 反漂移清单必写**——把"这个角色**不能**被画成什么"逐条写死（如主角禁协警警服/公文包/对讲机）。
4. **机检兜底**：**C26c**（年龄锚缺失）/ **C26d**（身份可渲染外观缺失）。

### VISUAL_IDENTITY_SYSTEM

每个 S/A 角色固定记录：

- `silhouette`：正面、3/4、侧面和背面仍成立的外轮廓。
- `shape_language`：圆、方、三角和不对称如何表达人物，不把形状当绝对人格公式。
- `palette`：主色、辅助色、强调色及使用比例；状态变化如何调整而不换人。
- `material`：服装和个人物件的主要材质、磨损与时代逻辑。
- `face_hair`：两至三个稳定脸发锚点，不堆十项细节。
- `body_posture`：重心、肩颈、手部和空间习惯。
- `signature_symbol`：最多一至两个有剧情意义的个人符号。
- `forbidden_drift`：不可改变的身份、年龄感、体态、轮廓和时代边界。

视觉身份至少定义轮廓、形状语言、主辅色、材质、脸发锚点、身体重心和一个主符号。

### 三秒识别与去装饰

执行：

1. `SILHOUETTE_TEST`：纯黑轮廓能否和主要角色区分。
2. `GRAYSCALE_TEST`：去掉颜色后，形状和材质层级是否仍可认。
3. `CROP_TEST`：半身、脸部或手部局部至少有一种稳定锚点。
4. `MOTION_TEST`：不看脸，只看站姿、走路和取物方式能否区分。
5. `SWAP_TEST`：互换服装或道具后是否全部失去身份；若是，说明人物本体太弱。

三秒识别来自结构与动作，不来自堆叠饰品；任意交换两个角色的服装细节后若仍无违和，说明视觉没有与人格和身份绑定。删除与身份、情绪、时代、剧情和关系都无关的装饰。超过三个主视觉锚点通常会降低识别和生成稳定性，标记 `VISUAL_OVERDESIGN`。

### 风格评分

对推荐主风格和最多两个备选风格分别按 1–5 评分：题材清晰度、情绪表现、角色一致性、动作可生成性、场景复用率、竖屏构图、资产成本和长篇耐看度。输出证据和代价，不因「流行」直接选择。同时从题材证据、情绪基调、目标画幅、动作复杂度和资产成本推荐主风格，说明备选与不推荐方案的代价。

### 身份提示词拆分

每个身份提示词拆成：身份块、造型块、表演块、镜头中性块和负面约束。身份主图使用单人、中性光线、中性表情和无叙事背景；行为图只展示已经锁定的记忆动作。

### IP_PRESENTATION_PACKAGE

面向用户检查的包装包必须包含：

1. 一句话灵魂和一句话市场识别。
2. 观众喜爱路径与可能反感点。
3. 三秒识别拆解：轮廓、动作、语言、关系。
4. 正面/3/4/侧面/背面、半身、面部、手部和个人符号的文字规格。
5. 常态、受压、真心、愤怒四组表演关键帧。
6. 主风格、备选风格和明确不推荐理由。
7. 可直接生图的身份主图、多视角、表情行为图提示词及负面约束。
8. `TEXT_SPEC`、`P0_DRAFT` 或 `APPROVED_R01` 状态，不得混淆。

## 1.12 跨题材 IP 适配器

题材适配器只改变分析重点和表现手段，不提供固定性格、服装、创伤或剧情答案。先从来源判断题材合同，再选择一个主适配器和至多一个辅助适配器；混合题材要说明谁决定角色内核、谁决定外在表达。

### 通用核心不变

所有题材都必须完成：来源证据、选择型灵魂、观众喜爱路径、真实缺陷代价、关系专属性、五类记忆点、视觉身份、表演声音和成长变体。适配器不能绕过这些核心，也不能把流行套路当成来源事实。

### 题材侧重点

**男频成长、逆袭与强者叙事**：重点检查能力如何被行动证明、尊严和责任底线、获得力量后的选择、胜利代价与对手有效策略。禁止把角色吸引力等同于财富、战力、身份碾压和所有人震惊。

**女频情感、婚恋与成长**：重点检查主体目标、情感边界、关系权力变化、照顾与控制的区别、被爱之外的能力和选择。禁止把「受欢迎、被宠、被争夺」当成人物灵魂。

**悬疑、犯罪与职业推理**：重点检查观察/判断方法、知识边界、秘密管理、职业伦理和真相代价。禁止用万能直觉、突然文件和创伤标签代替推理人格。

**喜剧与轻喜关系**：重点检查尊严目标与现实结果的落差、反应节奏、错误策略、关系接球方式和可变化的日常记忆点。禁止靠固定口头禅、降智和重复社死维持喜感。

**古装、权谋与历史幻想**：重点检查礼法身份、公开与私下语言、政治目标、权力姿态、服装层级和时代材料。禁止现代网络口吻、全员黑金华服和无来源的王者气场。

**玄幻、仙侠与超能力**：重点检查世界规则如何进入身体、能力使用、代价、伦理选择、轮廓和材质。禁止只靠发光特效、血统和等级制造识别。

**末日、生存与群像**：重点检查资源策略、群体位置、压力决策、人性底线、损失后的行为变化和装备功能。禁止全员战术黑衣、冷脸和同一种强硬说话方式。

**年代、现实与家庭伦理**：重点检查时代身份、劳动细节、社会限制、家庭权力、朴素情感和符合年代的色彩材质。禁止用现代审美直接覆盖人物处境，也禁止把受苦等同于讨喜。

**穿越、重生与身份错位**：重点检查原身份与新身份冲突、知识可用边界、改变既定事件的代价、语言伪装和双重关系位置。禁止让现代知识变成无成本万能外挂。

**恐怖、怪谈与暗黑幻想**：重点检查恐惧应对策略、规则认知、身体反应、道德边界和不可解释部分。禁止用苍白皮肤、红眼、黑衣等外观直接代替人物。

### 跨题材检查

对每个核心角色回答：如果把本角色移到另一题材，换掉服装和道具后是否仍完全成立？完全成立说明题材没有进入行为和价值；完全不成立说明人物只剩世界观装饰。合格结果应是稳定灵魂仍成立，但能力、压力、关系和表达必须依赖当前项目。跨题材测试至少选择与主项目差异最大的两个合成素材，验证不会重复输出同一套高冷、嘴硬、悲惨过去、黑红配色和固定小动作；发现固定答案时标记 `GENRE_TEMPLATE_IMPRINT`。

## 1.13 概念图模式

- 默认 `TEXT_SPEC_ONLY`：交付完整视觉规格和可直接生图的身份提示词，状态为 `TEXT_SPEC`。先让用户确认文字身份、轮廓和风格，再考虑生成。
- 用户明确要求生成概念图时才进入 `GENERATE_DRAFTS`；先锁文字身份块，再生成中性身份图、多视角图和少量行为/表情图，状态只能是 `P0_DRAFT`。逐项记录它锁定了什么、偏离了什么。
- 用户确认后才能升为 `APPROVED_R01`；未经确认的概念图不是正式资产，也不得反向改变人物来源事实。概念图若与来源或文字身份冲突，修改图，不修改原作人物。
- **裁定**：概念图的实际生成属于 sd-asset-engine 职责（人物立绘三风格模板）；本引擎交付文字规格与提示词，状态保持 `TEXT_SPEC`。

## 1.14 IP 质量门

`IP_QUALITY_GATES` 用来判断角色能否进入故事和剧本阶段，不判断市场一定爆款。所有结论必须引用来源、可执行设计或明确的用户确认。

### 十二项质量门

```yaml
IP_QUALITY_GATES:
  full_source_coverage: PASS
  source_fidelity: PASS
  choice_driven_soul: PASS
  audience_affection_path: PASS
  character_distinctiveness: PASS
  relationship_specificity: PASS
  visual_recognition: PASS
  performance_playability: PASS
  evolution_capacity: PASS
  production_consistency: PASS
  downstream_bindability: PASS
  genre_fit_without_template_copy: PASS
failure_flags: []
```

**`evolution_capacity` 门判据补充（★ 2026-10-13 增补 · 治「主角满级零转变」）**：本门除原有的「成长前后有真实差异且保留内核」外，**追加两条必判**——① `ability_start` 已填，且主角存在**可测量的能力盲区**（⛔ 不得开局满级、不得全员满级）；② `cognition_start` 已填，且全剧**至少一次**让认知盲区被事实击穿并改变行为。**缺任一条 → 本门判 `REVISE`**（判据见 §1.9.1）。**门数不变（仍十二项），本条是已有门的判据强化。**

### 八项识别与互换测试

1. `换名测试`：删除名字后，能否从选择、语言和行为认出角色。
2. `剪影测试`：去脸去颜色后，核心角色轮廓是否区分。
3. `盲听测试`：去掉说话人标签后，句式、节奏和关系态度是否可辨。
4. `角色互换测试`：把两名核心角色的行动互换；若剧情仍完全成立，角色策略克隆。
5. `关系互换测试`：把关系对象互换；若亲密、攻击和保护动作不变，关系没有专属性。
6. `缺陷代价测试`：删除人物缺陷后，剧情和关系是否不变；不变则缺陷只是标签。
7. `成长测试`：成长前后是否既有真实差异，又保留稳定内核。
8. `下游绑定测试`：能否给故事弧、分集和剧本提供具体选择、台词、行为、关系和视觉约束。

### 退回标记

出现任一未解决标记时不得锁定阶段②；不能通过清空数组掩盖正文问题。

- `SOURCE_INCOMPLETE`：已提供来源没有完整扫描。
- `ADJECTIVE_ONLY_SOUL`：灵魂只能用形容词描述，无法指向代价选择。
- `GENERIC_LIKABILITY`：只写善良、强大、可爱、悲惨，未说明观众喜爱过程。
- `CLONED_CHARACTER_VOICE`：核心角色句长、攻击、防御和承诺方式相同。
- `DECORATION_ONLY_MEMORY`：记忆点与身份、情绪、关系和剧情均无关。
- `RELATIONSHIP_SWAP_PASS`：关系对象互换后表现不变。
- `VISUAL_OVERDESIGN`：主锚点过多、层级混乱或无法稳定生成。
- `STATIC_SIGNATURE`：动作或口头禅机械重复，没有意义变化。
- `UNPAID_FLAW`：宣称缺陷，但从未造成选择或后果。
- `MAX_LEVEL_START`：主角开局即满级 / 全能，无能力盲区，全剧无一次因能力不足受挫（治「主角满级零转变」，见 §1.9.1）。
- `NO_COGNITIVE_SHIFT`：主角认知全书不变，无被事实击穿的盲区（治「零认知转变」，见 §1.9.1）。
- `UNSUPPORTED_WOUND`：虚构来源没有提供的创伤或秘密。
- `GENRE_TEMPLATE_IMPRINT`：把参考案例或流行题材模板写入当前角色。
- `DOWNSTREAM_UNBINDABLE`：人设无法转成故事选择、分集压力或剧本表演。

### 主编与观众双读

主编检查事实、差异、长线和生产；第一次观看的观众只回答：我为什么注意他、为什么喜欢或讨厌他、最记得哪个选择、哪个动作只能属于他、下一次想看他面对什么。两种读法都成立，才允许进入下游。

- **退回**：擅自新增关键身份/结局；核心对手没有有效目标；主角只依赖外挂或身份，自己没有选择与代价。

## 1.16 下游使用契约

阶段③—⑤必须读取并记录 `IP_CANON_MANIFEST` 版本。IP 只决定人物如何选择、表达、行动、相处和变化，不决定原作没有提供的事件结果。故事圣经用 `IP_ARC_BINDINGS`，分集卡用 `IP_DRAMATIZATION`，剧本清单用 `ip_bindings`；若下游可以删掉 IP 绑定而剧情完全不变，说明角色仍是模板人，必须退回。

## 1.17 阶段②禁止越界

不要用市场套路覆盖原作人物，不要虚构伤口、恋爱、身份、能力、关系和结局，不要让所有主角共享同一种高冷、嘴硬、善良或强大模板。不要为角色堆满无意义装饰、口头禅和小动作。不要在用户确认前把候选形象当成正式资产。

# 下篇 · 阶段③全剧开发圣经

## 2.1 门禁与输入

只读取锁定阶段②。`STEPWISE` 输出后停在 `AWAITING_CONFIRMATION`；`FULL_SCRIPT_PIPELINE` 只有通过故事校验清单后才能内部锁定阶段③。上游 `STALE`、IP 版本不一致或来源覆盖不完整时停止并报告。

读取全部原文、`SOURCE_MANIFEST`、`PROJECT_PROFILE`、锁定 `01_IP_BIBLE` 和 `01_ip/IP_CANON_MANIFEST.json`。长篇分块与续接处理见 [source-registration.md](source-registration.md) 第一节。

IP 清单中的来源事实、创作增强和开放项必须分开继承。阶段②决定人物如何选择、表达、行动和变化；阶段③用全书事件检验这些 IP，不得把增强候选伪装成原文事实。

阶段③的职责不是「概括每章发生了什么」，而是建立全剧可追溯的真值、变化、创作核心和改编策略，让分集编剧不用重新通读原文也能准确回答：

- 这是什么故事，最不可替代的创意是什么？
- 主角主动追求什么，谁以什么策略阻止？
- 观众持续等待哪些外部、情感和信息兑现？
- 世界规则如何限制行动并产生代价？
- 哪些人物选择体现锁定 IP，哪些缺陷必须支付后果？
- 哪些内容必须保留、可以压缩或允许重排？
- 按 1—3 分钟短集估算，故事具有多大的系列容量？

阶段③可以提出集数区间、事件级商业里程碑、钩子候选和叙事重排候选；不得锁定精确集数、把钩子分配给具体集、展开正式对白或决定镜头。

## 2.2 三遍通读

短篇与长篇都执行三遍；短篇可以在同一上下文完成，但不能省略任何一遍；长篇按 P1/P2 覆盖全部已提供来源。没有完成全源覆盖时只可输出 `PARTIAL_DRAFT`，不得锁定全局大纲、终局价值判断、集数区间或人物终局。

**第一遍：观众通读。** 不急于做表格，记录真实阅读反应：第一次产生兴趣、理解题材承诺和愿意继续读的位置；第一次明确共情、敬佩、厌恶或担心人物的位置；高概念第一次被动作证明而不是被说明的位置；阅读动力减弱、事件重复、规则混乱或情绪断裂的位置；最期待的三类兑现，以及结尾是否真正支付。产出 `AUDIENCE_READING_TRACE`。不要把个人喜好冒充市场事实；写清依据事件和可能对应的受众。

**第二遍：事实通读。** 按来源顺序锁定事件、因果、人物、关系、规则、状态、信息、伏笔、赌注和压力。每个关键事件至少能用下列链条复述：

`因为前提成立 → 人物想得到目标 → 采取行动 → 对手/规则反制 → 人物换策或支付代价 → 状态发生变化`

若只能写「发生了冲突」「有人震惊」「关系更差」，说明还没有识别有效事件。

**第三遍：改编通读。** 在事实锁定后判断表现形式、压缩合并、视觉化、信息延后、叙事重排、商业里程碑、钩子候选和系列容量：哪些叙述可以转成动作、道具、环境变化或关系行为；哪些重复说明可以合并、哪些重复是成长递进不能删；哪些事件适合成为大弧入口、中点、高潮和情感回收；哪些信息可以延后、哪些前提必须先建立；哪些事件允许冷开场、插叙、倒序或并行交叉；若重排，如何回到主时间线并维持人物知识边界。产出 `ADAPTATION_BLUEPRINT`、`HOOK_CANDIDATE_LEDGER` 和 `SERIES_CAPACITY_REPORT`，不改写来源事实。

## 2.3 P1 分块事实提取 与 P2 全局增量合并

**P1**：按自然章节边界处理未覆盖来源。为关键事件分配稳定 `EVT-####`，为来源角色映射锁定 `character_id`，为世界规则分配 `RULE-####`。记录来源范围、前提、触发、行动目标、主动行动、反制、结果、状态变化、信息可见范围、伏笔和压力。区分 `FACT`、`INFERENCE`、`ASSUMPTION`、`USER_OVERRIDE` 和 `OPEN_ITEM`。

**P2**：只处理新哈希与未覆盖范围，检查姓名别称、绝对/相对时间、身份、关系、地点、规则、资源、道具、伤势、知识边界和伏笔状态。原文不能解决时保留两个候选并标记 `OPEN_ITEM`，不得选择更戏剧化的版本冒充事实。

## 2.4 P3 全剧开发与改编诊断

先建立 `ORIGINAL_CREATIVE_DNA` 与 `AUDIENCE_GENRE_CONTRACT`，再写一句话、短梗概、完整梗概和大弧总纲。把世界秩序、规则限制与代价、主角价值、对立价值、主题问题和剧情证明写入 `WORLDVIEW_VALUE_CONTRACT`。为每个 S/A 角色建立故事小传和 `IP_ARC_BINDINGS`，让错误信念、缺点后果、喜爱支付、关系弧和记忆锚点落到来源事件。

最后建立七类 `ADAPTATION_BLUEPRINT`、事件级 `HOOK_CANDIDATE` 与 `SERIES_CAPACITY`。容量按有效事件、规则首建、关系支付、IP 选择、伏笔回收和说明负荷估算；允许单集 60—180 秒，默认约 90 秒，但完整故事单元和真实钩子位置优先。阶段③只给集数区间与推荐值，`exact_count_locked` 必须为 `false`。

## 2.5 原始创意 DNA

`ORIGINAL_CREATIVE_DNA.md` 固定回答：

1. 原始前提：人物在怎样的异常处境中必须做什么？
2. 核心机制：什么规则能持续制造新行动，而不是一次性噱头？
3. 核心梗：观众用一句话能复述的反差、关系或玩法是什么？
4. 欲望投射：观众借主角体验何种补偿、成长、爱情、正义或生存幻想？
5. 情绪承诺：爽、燃、甜、虐、笑、疑、惧分别来自什么事件结构？
6. 新鲜差异：与常见题材相比，哪一条具体规则或人物选择不同？
7. 长线发动机：故事为何可以不断升级，而不是重复同一冲突？
8. 传播记忆：三至五个来源支持的场面、台词功能、道具或选择候选。

**创意三层**：表层卖点（最容易被看到的身份、机制或处境）、中层引擎（能反复生成目标、阻力、代价与变化的冲突机制）、深层命题（人物在越来越高代价下反复回答的价值问题）。三层必须互相支持：只有表层卖点会快速耗尽；只有深层命题会缺乏短剧入口；中层引擎重复会造成每个大弧换人不换戏。

## 2.6 类型与受众合同

`AUDIENCE_GENRE_CONTRACT` 至少包含：主类型、次类型与题材外壳；核心目标受众和次级受众；受众进入故事的第一兴趣点；受众持续追看的长期问题；外部、关系、情感和信息四类承诺；观众可能弃看的原因；本项目不能丢失的类型满足；本项目不能机械复制的同类套路。

「年轻用户」「喜欢爽剧的人」不够具体。应说明他们期待看什么选择、关系、规则或兑现，以及什么重复会让他们失去兴趣。

## 2.7 一句话故事与多层梗概

在 `02_STORY_BIBLE.md` 和 `STORY_CANON_MANIFEST.json` 中同时建立四层：

- `one_sentence`：一句话包含主角 + 异常处境/独特机制 + 主动目标 + 主要阻力 + 最大代价。不要只罗列题材标签。
- `short_synopsis`：约 300—500 字，说明起因、目标、主要阻力、第一次有效行动、重大转折、高潮选择和结局方向。
- `full_synopsis`：按完整因果写清开始、发展、中点、危机、高潮、结局以及主要关系变化。不得用「经历一系列困难」「最终战胜敌人」跳过核心过程。
- `arc_outline`：按行动型大弧复述全剧，每弧写入口状态、目标、阻力、换策、代价、高潮选择、三类兑现、出口状态和下一弧债务。它是阶段④的直接宏观输入。

梗概必须覆盖结局；来源未完结时明确写 `SOURCE_INCOMPLETE`，不自行补完。

## 2.8 世界观和规则

`WORLDVIEW_VALUE_BIBLE.md` 与 `WORLD_RULE_LEDGER.json` 分开承担人类可读解释和机器状态。

**世界观层**：时间、地域、社会结构、阶层和日常秩序；阵营、组织、职业与利益关系；资源如何获得、流转、争夺和损耗；普通人在规则中如何生活，而不只描述强者；异常规则第一次进入日常的事件。

**规则层**：每条 `RULE-####` 记录 `source_trace`、`rule_statement`、`scope`、`activation_condition`、`capability`、`limit`、`cost`、`failure_consequence`、`known_by`、`effective_from_event`、`changed_by_event`、`status`。

能力没有限制和代价时，规则不能制造戏；规则没有在事件中影响行动时，只是背景设定。

## 2.9 价值观与主题冲突

不要用作者口号代替主题。建立 `WORLDVIEW_VALUE_CONTRACT`：主角认为世界应该如何运作；主要对立者认为世界应该如何运作；两种观点各自为何具有现实吸引力；主角观点的盲区和对立观点的真实反证；哪三个递增选择检验价值观；哪次选择造成关系或现实损失；结局通过行动肯定、否定或保留什么。

主题问题必须可被人物选择回答。例如「规则公平是否等于人的公平」可以进入利益分配、救援顺序和世界选择；「正义很重要」无法预测人物行动。

`dramatic_proof` 必须列事件：谁选择了什么、失去什么、世界因此发生什么变化。删除价值观描述后若事件不变，说明主题还没有进入剧情。

## 2.10 人物故事小传

`CHARACTER_STORY_BIOS.md` 不是重复阶段②的外形和性格，而是说明角色如何进入这一个故事。

每个 S/A 角色固定包含：`character_id` 与锁定 `ip_version`；原文身份、经历、当前状态和来源证据；外部目标、内部需要和当前错误策略；在主线中的不可替代功能；能主动推动的事件，不是只被卷入的事件；最有效的对手或关系阻力；起始、裂变、变化和终局状态；缺点造成的真实后果；观众喜爱点由哪次行动支付；关键关系建立、断裂、修复和回收事件；记忆锚点在全剧如何首用、变体和兑现；若删除此角色，哪些因果或情感必然失效。

B/C 角色可以使用轻量小传：身份、目标、阻力功能、信息权限、状态范围、合并风险和不可替代证据。

人物小传中的伤口、秘密、关系和能力必须来自来源或标为创作增强候选。不得为让人物「更立体」自动添加童年创伤、爱情、血缘或隐藏身份。

## 2.11 全剧大纲与大弧

### 核心问题

用一组可检验的问题统领全剧：外部问题（主角必须完成什么，失败的可见后果是什么）、内部问题（主角的旧策略为什么已不再有效）、关系问题（主角要获得目标必须与谁重新选择彼此）、世界问题（异常规则如何限制行动而非只提供便利）、受众承诺（观众持续等待哪三类兑现）。

### ARC 大弧卡

```yaml
ARC:
  arc_id: "ARC-##"
  title: "行动型名称"
  source_events: ["EVT-####"]
  entry_state: "目标、关系、信息、资源、危险的起点"
  driving_question: "本弧必须回答的问题"
  protagonist_goal: "可完成或失败的外部目标"
  opposition: "有目标、有策略的主要阻力"
  escalation_ladder:
    - "第一次有效行动"
    - "行动造成的新代价"
    - "信息改变后的新策略"
    - "不可回避的选择"
  midpoint_change: "使原计划失效的新事实或关系变化"
  climax_choice: "人物必须付出代价的行动"
  payoff: "外部、情感、信息分别兑现什么"
  exit_state: "五类状态发生了什么变化"
  unresolved_debt: "交给下一弧的具体问题"
  confidence: "FACT/INFERENCE/ASSUMPTION"
```

大弧的高潮必须是人物行动产生的结果。若删除主角仍会自然解决，说明主角没有推动故事；若每次升级只换一个更有权势的敌人，说明冲突引擎重复。

额外检查：大弧名称必须描述行动，不用「成长篇」「感情篇」一类标签；每弧至少存在一次有效反制和一次策略改变；每弧高潮由人物选择造成，不由巧合或救兵自动完成；每弧至少支付外部、情感、信息中的两类承诺；连续三个大弧不得共享同一冲突公式；下一弧继承新状态，不重复上一弧已经解决的争吵。

全局大纲应同时保留来源顺序和建议呈现顺序。来源顺序是事实；建议呈现顺序是候选，必须通过重排审计后才能交给阶段④。

### IP_ARC_BINDINGS

在事件因果账之前，先为每个 S/A 级角色建立可被分集消费的 `IP_ARC_BINDINGS`：

```yaml
IP_ARC_BINDINGS:
  character_id: "CHAR-####"
  ip_version: "v1.0"
  stable_core: "全剧不可漂移的价值核与人格矛盾"
  false_belief_under_test: "本弧被事件反复检验的错误信念"
  choice_escalation: ["低成本选择", "关系代价选择", "不可逆选择"]
  flaw_consequence: "缺点在本弧具体造成的损失"
  affection_payoff: "观众为何在本弧更理解、敬佩、心疼或想追随他"
  relationship_arc: "关键关系如何因双方行动改变"
  memory_anchor_evolution: "行为/语言/视觉/关系锚点如何变体或兑现"
  forbidden_drift: ["本弧不得出现的人格捷径"]
```

`stable_core` 不能写成「高冷、善良、聪明」一类空泛形容词；必须能预测人物在两难处境中的取舍。`memory_anchor_evolution` 不是每弧机械重复口头禅或招牌动作，而是让同一识别锚点在压力、关系和成长状态下产生新含义。

### 事件因果账

`EVENT_LEDGER.json` 的关键事件至少记录：

```yaml
event_id: "EVT-####"
source_trace: ["source_id:range"]
precondition: ["发生前必须成立的事实"]
trigger: "引爆事件"
actor_goal: "行动者此刻想得到什么"
action: "行动者主动做了什么"
counteraction: "谁如何反制"
result: "可见结果"
state_change: "目标/关系/信息/资源/危险的变化"
causes: ["EVT-####"]
enables: ["EVT-####"]
```

「有人生气」「双方争吵」不是充分事件，除非它改变承诺、关系或后续行动条件。

## 2.12 信息差、伏笔、状态与赌注账本

### 信息差矩阵

`INFORMATION_MATRIX.md` 按事实列出观众、主角、盟友、对手分别处于 `KNOWS`、`SUSPECTS`、`BELIEVES_FALSE` 或 `UNKNOWN`，并记录生效事件。身份悬念的张力来自谁知道什么以及谁据此行动，不来自作者故意隐瞒已经被人物说出口的信息。

| 信息项 | 观众 | 主角 | 盟友 | 对手 | 释放事件 | 行动后果 |
|---|---|---|---|---|---|---|
| INFO-### | 状态 | 状态 | 状态 | 状态 | EVT-#### | 谁改变策略 |

### 伏笔与回收账

`SETUP_PAYOFF_LEDGER.md` 同时管理身份、道具、规则、承诺、创伤和关系行为。

| 账项 | 类型 | 种下事件 | 当时表层功能 | 二次提醒 | 计划回收事件 | 回收方式 | 状态 |
|---|---|---|---|---|---|---|---|
| SP-### | 道具/信息/承诺 | EVT | 不泄底的当下作用 | EVT/无 | EVT/待定 | 行动、证据或选择 | PLANTED/REMINDER/PAID/OFFENDED |

伏笔第一次出现必须有当下功能，不能只为未来强行摆设；回收必须改变人物决定或局势。已经回收的账项不得再次当作全新秘密。

### 状态连续账

人物关系、伤势、资源、职业、地点控制权、道具归属和造型变化都记录 `effective_from_event` 与可选 `effective_until_event`。状态变化先进入账本，再允许下游使用，防止人物突然康复、知道秘密或持有不存在的道具。

### 赌注与后果阶梯

为每条主线登记 `STAKE_CONSEQUENCE_LADDER`：观众何时知道人物可能失去什么、谁有能力让损失发生、第一次警告、第一次真实损失、不可逆后果和最终支付。资格、项目、婚姻、生命或身份不能在人物拿来施压时才第一次出现。

| stake_id | 赌注 | 建立事件 | 首次受压 | 首次真实后果 | 不可逆节点 | 谁推动后果 |
|---|---|---|---|---|---|---|
| STK-### | 具体可失去项 | EVT | EVT | EVT | EVT/待定 | 有目标的行动者或规则 |

「可能被问责」不是后果；被暂停权限、失去机会、公开站队、交出证据、关系破裂或时限缩短才是可观察状态变化。

同时建立 `SOURCE_PRESSURE_LEDGER`，把每项来源压力拆成：原文措辞/原意、开始时间、触发条件、作用对象、后果强度、来源范围和当前状态。下游可压缩表达，不得改变逻辑量词：`可能` 不能变成 `一定`，`三天后未完成` 不能变成 `今天停止就立即发生`，`面临审查` 不能变成 `已经被取消资格`。用户若明确授权改变，登记为 `USER_OVERRIDE`，否则维持 `UNCHANGED`。

### 情感证据链

伤口和关系不能只停留在人物小传。为核心情感记录：触发物、身体/语言反应、人物试图隐藏什么、它如何改变一次策略、人物最终为此支付或放弃什么。若删除情感设定后人物行动完全不变，说明情感线尚未进入故事。

## 2.13 商业追看承诺

商业性来自「兑现后打开更大问题」，不是永远拖延答案。阶段③登记事件级里程碑：

高概念第一次可视化；主角无法退出的损失和目标；第一次有效能力验证；关键关系结盟或决裂；第一次完整外部与情感兑现；更大目标建立；中段规则重估；核心秘密的来源支持反转；不可逆失败或代价；最终选择与情感回收。

每个里程碑绑定 `EVT`、`ARC`、`IP_ARC_BINDINGS` 和来源范围。阶段③只登记适合形成追看承诺的事件，不分配集号。推定只可组织已有事实或补足连接动作，不能生成新的核心证据和答案。原文未提供真正身份、失踪原因、关键道具来源、隐藏文件、机关或最终胜负时，相关里程碑写为 `OPEN_ITEM`，不得因为交付集数较少就自动创造谜底；闭合人物当下行动，不闭合来源未回答的事实。

## 2.15 改编蓝图：七类改编决策

改编可以改变呈现顺序、信息密度、场面组织和表达媒介，但不能无授权改变：主线的目标、关键因果和重大结果；人物做出关键选择的真实动机；世界规则的能力、条件、限制与代价；已经建立并在后文回收的伏笔；关键关系的形成、背叛、修复和终局位置；具有独特功能和情感意义的来源台词。

「为了节奏更爽」不是改变核心事实的授权。增强只能在不改变核心事实的连接动作、可见反应、职业流程、空间调度和信息组织中进行，并标为 `INFERENCE` 或 `ASSUMPTION`。

**`MUST_KEEP`**：保留主线因果、关键选择、核心规则、关键台词功能、关系转折和伏笔回收。记录来源范围与事件 ID、必须保留的功能、允许改变的表达形式、删除后会破坏什么。

**`COMPRESS`**：压缩重复解释、重复升级、重复围观反馈、功能相同的流程和对主线无新增状态的往返。压缩后必须保留因果前提、人物为何改变策略、第一次有效建立和最后一次完整兑现、关系与世界状态变化。若重复行为本身用于证明习惯、升级代价或关系恶化，不能全部压成一句。

**`MERGE`**：合并功能相同的次要人物、场所、会议或阻力节点。合并前检查：两者是否拥有不同信息权限；是否分别承担不同伏笔；是否在不同关系中产生独特选择；合并后是否造成角色知道不该知道的信息；是否让一次背叛、救援或见证失去情感意义。名称不同但功能相同不代表必须合并；功能相似但信息与关系不同也不能合并。

**`VISUALIZE`**：把叙述、心理和设定转成可见可听的行为证据——心理怀疑 → 核对记录、停手、改变站位或试探对方；身份压力 → 权限失效、称谓变化、座位调整或资源被收回；关系疏远 → 停止专属行为、拒收物品、改用正式称谓；世界规则 → 能力失败、代价出现、环境响应或普通人改变行为。视觉化不能新增能够回答核心谜底的证据，也不能让人物提前暴露秘密。

**`REORDER_CANDIDATE`**：允许冷开场、倒序、插叙、并行交叉和多视角，但当前只登记候选，不直接改变事实顺序。每项写：来源时间顺序、建议呈现顺序、预期观众收益、进入点和回到主时间线的位置、被提前展示的信息、必须隐藏的信息、因果知识和情感风险、`CANDIDATE/REJECTED` 状态。

**`DEFER`**：延后解释或释放已经存在的事实。延后必须满足：人物仍能依据当时可见信息做出合理行动；观众不会把必要因果误解成编剧漏洞；延后位置有来源支持的证据或人物行动可兑现；不重复假揭露同一秘密。

**`FORBIDDEN_CHANGE`**：明确禁止——新增来源不存在的幕后身份、血缘、暗号、隐藏文件或能力来源；把条件式压力改成已经发生的惩罚；为制造爽点让人物违背锁定 IP 且不承担后果；把对手降智以便主角赢；把未完成原作强行写成闭合结局；为缩短集数删除人物作出关键选择的前提。

### 场景化候选（DRAMATIZATION_CANDIDATE）

为每个重要叙述段落填写：

```yaml
source_trace: "SRC-###:范围"
source_function: "这段叙述提供何种因果、情感或规则"
visible_evidence: "观众能看到或听到什么"
active_character: "谁为了目标采取行动"
opposition_response: "谁或规则如何反制"
state_change: "动作后发生什么变化"
protected_information: "不能提前泄露什么"
confidence: "FACT/INFERENCE/ASSUMPTION"
```

不能只把旁白拆成人物轮流朗读。若没有行动、阻力和变化，仍然只是换了说话者的说明文。

## 2.16 混编、倒序与插叙：六项重排门禁

每个 `REORDER_CANDIDATE` 必须通过六项门禁：

1. **因果门**：观众可以暂时不知道原因，但人物行动所需的原因必须已经真实发生。不能让未来结果反向成为过去行动的动机。
2. **知识边界门**：重排后分别记录观众、主角、盟友和对手知道什么。人物不能使用只向观众展示的信息。
3. **悬念保护门**：冷开场展示危险或结果时，避免同时泄露依赖身份、方法或关系选择的真正答案。展示「发生了什么」不等于展示「谁、为什么、如何做到」。
4. **返回路径门**：明确何时、以何种动作、声音、道具或时间标记回到主时间线。不得连续多集停留在解释性回忆，使主行动失速。
5. **情感支付门**：如果提前展示死亡、背叛或胜利，会不会让之前的关系选择失去不确定性？若会，只能展示不完整结果或拒绝该候选。
6. **来源忠实门**：重排改变的是观众获取信息的顺序，不是事件真实发生的顺序、人物动机或结果。两套顺序必须同时保存在账本中。

通过六门后状态仍为 `CANDIDATE`，由阶段④根据全剧节奏决定是否采用。

## 2.17 钩子候选池

`HOOK_CANDIDATE_LEDGER.md` 只登记来源支持、存在具体等待问题且有兑现事件的候选。

| 字段 | 要求 |
|---|---|
| `hook_id` | 稳定 `HKC-####` |
| `hook_type` | ACTION/CHOICE/EVIDENCE/ARRIVAL/DANGER/IDENTITY/EMOTION |
| `source_events` | 产生钩子的事件 |
| `waiting_question` | 观众下一步等待的唯一具体答案 |
| `payoff_events` | 来源支持的部分或完整兑现事件 |
| `source_trace` | 原文范围 |
| `spoiler_risk` | 是否提前破坏更大秘密 |
| `relationship_or_value_effect` | 兑现后改变哪段关系或判断 |
| `status` | `CANDIDATE/REJECTED`；交给阶段④的只能是 `CANDIDATE` |

阶段③不填写 `episode_id` 或 `payoff_episode`。同一来源秘密不能拆出多个含义相同的假钩子。

**有效钩子的最低条件**：等待对象具体；已有来源事件建立问题；已有来源事件能够兑现；兑现会改变行动、关系、信息或危险；不依赖突然出现的身份、巧合或资源；可以在后续动作中兑现，不只靠解释。

**钩子与拖延的区别**：有效——本阶段完成一次局部目标，新的证据让下一行动问题升级；拖延——在答案说出口前切黑，下一集只是补完同一句话。有效——人物已经做出选择，观众等待选择造成的后果；拖延——人物正准备选择，连续多集不作答。

## 2.18 系列容量诊断

`SERIES_CAPACITY_REPORT.md` 不从平台常见集数反推故事，而从来源的有效戏剧负荷估算。

**统计单位**：`EVENT_LOAD`（具有目标、反制、代价和状态变化的主事件）、`ARC_LOAD`（需要独立入口、升级、高潮和回收的大弧）、`RULE_LOAD`（必须通过行动建立的世界规则）、`RELATIONSHIP_LOAD`（建立、断裂、修复和回收节点）、`IP_LOAD`（核心角色错误信念被考验及记忆锚点变体）、`SETUP_PAYOFF_LOAD`（不能删除的伏笔、承诺、证据与回收）、`EXPOSITION_LOAD`（必须理解但可以视觉化或压缩的信息）。

**事件可压缩性**：每项标为 `ATOMIC`（不能与其他事件合并，否则失去选择或后果）、`COMBINABLE`（与相邻事件目标、地点和阻力相容，可同集完成）、`MONTAGEABLE`（重复过程可压缩，但必须保留首建和最终变化）、`CALLBACK_ONLY`（后续只需承接或回看，不重复计为主事件）。

**情感与规则占用**：高信息事件不一定能独占一集，但关键关系选择、世界规则首建和不可逆损失需要建立与反应时间。容量估算必须包含：观众理解前提的时间、人物行动与对手反制的时间、策略改变的时间、情感或后果被看见的时间、钩子停顿和下一集承接的空间。只按章节数、字数或打斗次数估算会产生碎片化分集。

## 2.19 集数区间与时长

**时长合同**：允许单集 60—180 秒；默认估算约 90 秒；最终时长服从完整故事单元和真实钩子位置，不机械凑到 90 秒；同一地点、时间、目标和策略不能只因超过 90 秒被从中间切断；若完整局部兑现需要 110 秒，应优先保留完整性；若一个完整事件只需 75 秒，不用填充重复对白。

**集数报告**固定输出：

```yaml
duration_min_seconds: 60
duration_default_seconds: 90
duration_max_seconds: 180
episode_range_min: 具体整数
episode_range_max: 具体整数
recommended_episode_count: 区间内建议值
exact_count_locked: false
basis: "事件、关系、规则、伏笔和钩子负荷依据"
flexibility_rule: "完整故事单元与有效钩子优先"
```

阶段③只给范围和推荐值。阶段④结合用户目标、事件覆盖和真实断点锁定精确集数。若用户预设集数明显小于最低容量，报告必须删除或合并的内容、会失去的因果人物弧或回收、可行的短版范围、不可接受的魔改风险。若预设集数明显大于最高容量，报告可扩展的关系与规则行动，禁止用重复争吵、围观震惊、误会和空钩子注水。

## 2.20 向分集阶段交接

阶段④必须读取：`STORY_CANON_MANIFEST.json`、`02_STORY_BIBLE.md`、`ADAPTATION_BLUEPRINT.md`、`SERIES_CAPACITY_REPORT.md`、`HOOK_CANDIDATE_LEDGER.md`、`WORLDVIEW_VALUE_BIBLE.md`、全部事件、人物、规则、信息和伏笔账本。

交接卡列出：锁定 IP 版本；全部必用事件与可压缩事件；每个大弧的入口、高潮、出口和债务；允许采用的叙事重排候选及六门审计结果；可用钩子候选和兑现事件；建议集数区间、默认时长与用户目标冲突；不可修改项与仍未解决的开放问题。

阶段④若不使用推荐集数，应记录调整理由和受影响事件；若选择重排候选，应把呈现顺序写入分集计划，但不得修改来源时间线。

## 2.21 失败模式与架构审计

**失败模式**：按原著章节一章一集，忽略事件负荷；只写宏观概括，没有稳定事件 ID 和来源范围；把「核心梗」写成题材标签；价值观只有口号，没有对立观点、选择和代价；人物小传重复外貌性格，没有全剧行动功能；世界规则只有能力，没有限制、代价和失败后果；为了强钩子提前泄露来源依赖的核心谜底；把一句未说完的话当成钩子候选；用 `INFERENCE` 新增血缘、证据、能力来源或结局；精确锁死集数，逼阶段④机械切碎连续场景；用统一「打脸、震惊、身份揭露」模板覆盖所有题材。

**架构审计**逐弧回答：主角主动做了什么？对手为什么能造成有效阻力？哪个信息改变了策略？哪个关系选择让胜负有情感意义？付出了什么不能立即抹平的代价？种下的道具、身份或承诺在哪里回收？下一弧继承的是新局面还是同一争吵？重要赌注是否先建立后调用并至少产生一次真实后果？核心情感是否改变人物策略，而非只靠道具触摸和台词说明？每项压力的开始时间、触发条件、对象和后果强度是否与来源一致？

存在无来源重大反转、前置条件缺失、状态互相冲突或三条以上长期伏笔无计划回收时，不得通过阶段③。

## 2.22 阶段③自检与锁定

逐项检查：全源覆盖、原始创意 DNA、类型受众合同、四层梗概一致、世界规则可行动、价值冲突由选择证明、因果完整、人物弧消费锁定 IP、信息边界、伏笔回收、改编忠实、重排安全、钩子有来源与兑现、容量有事件依据、阶段④可直接消费。

十五项 `STORY_QUALITY_GATES`（全源覆盖、创意DNA、受众合同、梗概一致、规则可行动、价值由选择证明、因果完整、IP弧消费、信息边界、伏笔回收、改编忠实、重排安全、钩子来源与兑现、容量依据、下游可消费）全为 `PASS`、`failure_flags` 为空、推荐集数位于区间内、`exact_count_locked` 为 `false`、每个钩子候选拥有来源事件与兑现事件，才能锁定阶段③。

只有设定没有行动后果、只有人物形容词没有选择、只有反转没有前置证据、用集数惯例代替容量诊断、或重排破坏因果和知识边界时必须返修。

完成标准——阶段③通过前必须能够：用一句话和完整梗概讲清同一个故事，不互相矛盾；从任何重大结论追溯到 `EVT` 或来源范围；从任何人物弧追溯到选择、阻力、代价与状态变化；从任何世界规则追溯到限制、代价和实际影响的事件；从任何主题结论追溯到对立价值和人物选择；从任何钩子候选追溯到来源事件与兑现事件；解释建议集数区间来自哪些事件负荷，而非行业惯例；清楚区分来源事实、结构推断、连接补足、用户授权和开放问题；让阶段④在不重新发明故事的情况下完成全剧分集。

## 2.23 阶段③禁止越界

不要提前决定精确集数、具体单集钩子、集尾断点、正式对白、资产、镜头或视频提示词。不要按原著章节机械换算集数，不要为增强爆点新增来源没有提供的身份、血缘、证据、能力来源、规则、重大胜负或结局，不要把未完结来源自动补完。
