# 来源登记与源头处理

> 精编自《灵境AI剧本改编 skill》（6阶段编剧链）

本文件覆盖阶段①的三件事：来源登记（SOURCE_MANIFEST 与长篇分块处理）、源头人物挖掘（全篇角色证据扫描）、源本改编与裁剪（原作主导改编与删减审计）。前两项是阶段①②的主输入，第三项在阶段⑤正式剧本中执行。

## 一、来源登记

### 1.1 SOURCE_MANIFEST

`SOURCE_MANIFEST.json` 为每块来源记录：

- `source_id`：稳定来源键。
- 文件或消息标识。
- 章节起止。
- 字符或页码范围。
- 内容哈希。
- 读取状态、提取状态和合并状态。

### 1.2 材料类型自动识别

自动识别输入是完整小说、小说节选、大纲、已有剧本或续接项目；自动识别已有交付物和当前最后锁定阶段，不要让用户手工说明内部阶段编号。模式未确定前只登记来源和识别材料类型，不生成正式 IP。

### 1.3 长篇分块与合并

- **分块**：优先使用自然章节边界；没有章节时再按长度分块。分块之间保留小范围重叠只用于识别承接，事件不得重复入账。
- **合并**：比较姓名与别称、时间线、身份、关系、地点、道具、伤势、知识边界和伏笔状态。相同事实合并来源；变化事实保留生效事件。
- **冲突**：先按原文证据强度和时间顺序解决。无法解决时保留两个候选，分别列证据并写入 `OPEN_ITEM`，不得选择更戏剧化的版本冒充事实。
- **续接**：新批次只处理未覆盖内容哈希。续接前读取现有事件与人物账本，不重新编号已经锁定的 ID。

### 1.4 项目状态文件

每个项目创建：

- `projects/<project-id>/SCRIPT_PIPELINE_STATE.json`
- `projects/<project-id>/PROJECT_MANIFEST.md`
- `projects/<project-id>/00_source/SOURCE_MANIFEST.json`

阶段状态只允许：`NOT_STARTED / IN_PROGRESS / AWAITING_CONFIRMATION / AWAITING_USER_DECISION / LOCKED / STALE / BLOCKED`。锁定输入发生改变时，从变更阶段向下传播 `STALE`，不得静默沿用旧版本；受影响的剧本、资产与下游包同步标记。

## 二、源头人物挖掘：全篇角色证据扫描

IP 设计必须来自整本已提供材料，而不是只读简介、开篇或作者形容词。目标是得到可复核的全篇角色证据，再决定哪些内容属于稳定内核、阶段状态、他人误解或创作候选。

### 2.1 P1 分块扫描

长篇按章节、卷或自然剧情块处理。每块建立 `CHARACTER_EVIDENCE_LEDGER`：

| 字段 | 内容 |
|---|---|
| evidence_id | `CE-####` |
| character_id | 稳定角色键 |
| source_trace | 来源与准确范围 |
| evidence_type | 作者说明/自述/他评/重复行为/关键选择/失败后果/关系行为/视觉声音 |
| context | 当时目标、压力、知识和关系状态 |
| action_or_line | 人物实际做了什么或说了什么 |
| cost_or_result | 行为产生的代价与结果 |
| reliability | HIGH/MEDIUM/LOW |
| possible_meaning | 可支持的人格结论，不直接冒充事实 |

证据权重默认：重大代价下的重复选择 > 造成后果的行动 > 多次稳定行为 > 人物私下自述 > 他人评价 > 作者标签。评价与行动矛盾时同时保留，交给 P2 判断，不静默选择更讨喜的版本。

### 2.2 P2 全篇合并

合并所有 P1 证据，分别判断：

- `STABLE_CORE`：跨阶段仍稳定的价值选择。
- `START_STATE`：人物早期使用的自保策略。
- `CONTEXT_STATE`：仅在特定身份、关系或危险下出现。
- `PUBLIC_MASK`：人物希望别人看见的样子。
- `PRIVATE_SELF`：独处或安全关系中出现的行为。
- `ARC_CHANGE`：由事件和代价触发的真实变化。
- `CONTRADICTION_TO_RESOLVE`：来源内部尚未解释的冲突。
- `OPEN_ITEM`：已提供材料无法回答。

全篇角色证据必须覆盖：首次出场、至少一次主动目标、至少一次受压选择、至少一次失败或代价、主要关系变化、能力边界、结局或当前最新状态。来源确实没有某项时写 `OPEN_ITEM`，不得自动发明童年伤口或秘密。

### 2.3 角色层级

- `S`：作品情感和商业识别核心；建立完整灵魂、视觉、声音、关系与成长系统。
- `A`：长期核心对手、搭档或关系对象；完整建立，但视觉层级不得抢走 S 角色主识别。
- `B`：反复出现且承担独特功能；只建立必要灵魂、声音和关系边界。
- `C`：一次性功能人物；留给资产阶段，不在本阶段过度包装。

层级看故事影响和长期复用，不看财富、战力或戏份单一指标。

### 2.4 通用性防线

测试案例、参考剧本和流行角色只能贡献抽象方法，不能贡献默认答案。检查输出中是否出现与本项目来源无关的固定职业、道具、色彩、创伤、亲属失踪、重生秘密或身份揭露；出现即标记 `GENRE_TEMPLATE_IMPRINT`。

### 2.5 完成条件

`source_coverage.coverage_status` 只有在全部已提供来源都完成 P1、完成 P2 合并、别名和时间状态冲突已处理、`unresolved_ranges` 为空时才能写 `COMPLETE`。尚未收到小说后续不算遗漏，但必须明确「当前只覆盖已提供范围」，终局类字段保持 `OPEN_ITEM`。

## 三、源本改编与裁剪：原作主导改编与删减审计

> 本节在阶段⑤正式剧本中逐集执行；阶段②③建立改编蓝图时同样遵循其核心原则。

### 3.1 改编不是另写故事

阶段⑤的创作空间存在于「如何把原作写得更可看、更可演」，不在「替原作发明更刺激的主线」。判断一项改动能否执行，先问：

1. 它是否改变观众对事实、责任、关系、规则或结局的判断？
2. 它是否改变人物为什么行动、何时知道、能做什么或必须付什么代价？
3. 删除它后，后续事件、伏笔、情绪和台词是否仍能自然成立？

任一答案涉及核心变化，就不是阶段⑤可自行处理的连接优化。

### 3.2 四级来源比对

每集建立 `SOURCE_ADAPTATION_PACKET`：

| 层级 | 核对内容 | 不一致时处理 |
|---|---|---|
| 小说原文 | 事实、顺序、人物动机、知识边界、关键台词 | 原文为最高事实权威 |
| 故事圣经 | 事件 ID、因果、世界规则、关系和伏笔 | 修正结构化误读或退回阶段③ |
| 分集卡 | 主事件归属、单集承诺、局部兑现、主钩子 | 退回阶段④，不在剧本中静默改动 |
| 正式剧本 | 场次、行动、对白、表演和节奏 | 重写至与前三层一致 |

每个条目至少记录：

```yaml
source_event_id: EVT-0001
source_trace: "SRC-001:第12—15段"
adaptation_mode: KEEP
source_function: "建立主角为何必须拒绝交易"
script_scene_ids: ["EP001-SC02"]
preserved_result: "拒绝仍由保护弟弟的动机触发，并导致失去资源"
causal_protection: "EP002 的追责和关系裂痕仍有成立条件"
decision_reason: "核心选择，必须原意保留"
```

### 3.3 七种改编动作

**`KEEP`**：用于主线因果、核心选择、关键关系、世界规则、伏笔回收和不可替代的关键台词。允许口语化和可视化，但事实、功能、关系位置和发生条件不变。

**`COMPRESS`**：压缩重复解释、同一结论的多次内心独白、无独立结果的往返过程。压缩后仍要让观众知道：人物为何采取行动、对手如何反应、什么发生了变化、代价或情绪为何成立。

**`MERGE`**：合并同功能场次、过程或次要人物功能。禁止因合并而把不同人的责任、关系位置、知情范围或关键选择交给错误人物。

**`VISUALIZE`**：把叙述转成可观察的行为。优先顺序：`行动结果 > 对手反应 > 空间/道具证据 > 策略对白 > 极少量旁白`。可视化不能创造新的证据。例如「她怀疑账本被改过」可以写成她对比页码、停下签字；不能凭空新增鉴定报告证明账本造假。

**`REORDER_AUTHORIZED`**：只执行故事圣经或分集卡已登记的重排。重排后仍须保护：原因先于结果；人物先获得信息再据此行动；赌注先被建立再被调用；伏笔先种下再回收；原作事实的实际生效顺序不被伪造。

**`DELETE_REDUNDANT`**：只删没有独立因果、人物、关系、情绪、主题、伏笔或节奏功能的重复内容。主事件和 `MUST_KEEP` 永不使用此标签。

**`CONNECTIVE_INFERENCE`**：只补充入场、移动、拿取、停顿、职业流程、生活化反应和必要连接对白。新增内容必须同时满足：不改变核心事实；不改变人物动机和知识边界；不提供来源未给出的答案；删除后不影响故事走向，只影响呈现顺畅度。

### 3.4 删减影响审计

删减不是「觉得拖沓就删」。每项删除都填写：

```yaml
audit_id: DEL-EP001-01
source_trace: "SRC-001:第18—21段"
removed_content: "第二次重复解释比赛规则"
reason: "观众已在行动场中理解，重复说明不产生新反制"
original_function: "再次说明截止时间"
replacement_carrier: "EP001-SC01 的倒计时屏显与对手催促"
causal_chain_status: PRESERVED
motivation_status: PRESERVED
setup_payoff_status: NOT_APPLICABLE
decision: SAFE_DELETE
```

审计必须继续向后看至少一个事件链和相邻集。以下任一情况不得删除：

- 它是人物改变策略的理由。
- 它建立了后续会被调用的赌注、知识、关系或道具状态。
- 它是伏笔、误导、回收或关键台词的必要语境。
- 它让观众理解「为什么现在」和「为什么是这个人」。
- 它承担关系付出、情绪积累或后果见证。

找不到替代承载或无法证明影响时，`decision` 不能写 `SAFE_DELETE`。

### 3.5 关键台词保护

关键台词不等于逐字照搬所有小说句子。保护顺序是：

1. 事实和语义。
2. 说话人与关系位置。
3. 当下行动目的。
4. 冲突或情绪功能。
5. 原句中真正有辨识度的措辞。

每句关键台词只设一个 `PRIMARY_USE`。若原句不适合口语，可进行 `SEMANTIC_PRESERVE`，但要登记直白语义主干，证明没有改写事实。若法规或平台尺度必须调整，标记 `USER_AUTHORIZED` 或项目合规决策，保留功能与影响。

### 3.6 禁止的「优化」

- 用更强身份、更大财富或突然援军替代人物解决问题。
- 为卡点新增来源不存在的照片、录音、合同、鉴定、秘密身份或超能力。
- 把人物谨慎改成无脑挑衅，把人物善良改成无底线忍让。
- 为追求快节奏删掉动机、反制、反应和代价，只留下事件结论。
- 把复杂人物改成热门标签，把原作冲突换成连续打脸或重复羞辱。
- 把未揭晓谜底提前写死，把条件风险写成已发生事实。

出现上述情况分别标记 `UNAUTHORIZED_PLOT_INVENTION`、`SOURCE_MOTIVATION_DRIFT`、`MECHANICAL_FAST_PACING`、`TROPE_REPLACEMENT` 或 `UNSOURCED_CORE_CHANGE`。
